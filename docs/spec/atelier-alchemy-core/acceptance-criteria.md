## REQ-001〜REQ-008: 庭（仕込み層）🔵

**信頼性**: 🔵 **新設（2026-07-09、QAレビューCritical指摘「庭システムのTCが1件も存在しない」への対応）** *コンセプト文書5章「庭（仕込み層）の仕組み」より*

### Given（前提条件）
- 庭にスロットの空きがある
- プレイヤーが種を所持している

### When（実行条件）
- プレイヤーが種を植える、または成熟した素材を収穫する

### Then（期待結果）
- スロット数の制限内でのみ植栽できる（マス配置なし）
- 成熟後は放置で品質が上昇するが、規定の猶予ターンちょうどで枯死する
- 収穫時に特性が1つ、分散のみの乱数で付与される

### テストケース

#### 正常系

- [ ] **TC-001-01**: 空きスロットに種を植える 🔵
  - **入力**: 空きスロットを選択し、所持する種を植える
  - **期待結果**: 庭スロットに種が配置され、成熟ターン数のカウントが開始する
  - **信頼性**: 🔵 *REQ-001より*

- [ ] **TC-004-01**: 成熟後に放置すると品質が上昇する 🔵
  - **入力**: 成熟済み素材（品質B相当）をさらに1ターン放置する
  - **期待結果**: 品質がB→Aへ上昇する（枯死猶予ターン内であること）
  - **信頼性**: 🔵 *REQ-004より*

- [ ] **TC-006-01**: 収穫時に特性が1つ付与される 🔵
  - **入力**: 特性候補を複数持つ種を収穫する
  - **期待結果**: 収穫された素材の特性タグが0〜2個の範囲内で、候補のいずれか1つが付与される
  - **信頼性**: 🔵 *REQ-006より*

- [ ] **TC-006-S01**: 特性乱数の分散が期待値を変えないことを統計的に確認する 🟡
  - **入力**: 同一種を統計的に十分な回数（例: 100回以上）収穫する
  - **期待結果**: 各特性候補の出現比率が設計上の期待値から有意に偏らない（分散のみで期待値は不変というREQ-006の性質を統計検証）
  - **信頼性**: 🟡 *REQ-006「分散のみで期待値は変えない」より妥当な推測。具体的な統計的許容範囲は実装フェーズで確定*

- [ ] **TC-007-01**: 成熟前の素材は収穫できない 🔵
  - **入力**: 未成熟の素材に対して収穫を試みる
  - **期待結果**: 収穫操作が拒否される（EDGE-003）
  - **信頼性**: 🔵 *EDGE-003「確定（2026-07-09）」より*

- [ ] **TC-008-01**: 調合から逆算して特性を狙った種を選択できる 🟡
  - **入力**: 日替わり指定調合物が要求する特性に対応する種をショップまたは庭で選択する
  - **期待結果**: 該当特性を狙える種が選択肢に提示される
  - **信頼性**: 🟡 *REQ-008「注文生産」より妥当な推測。UIの具体的な提示方法は実装フェーズで確定*

#### 異常系

- [ ] **TC-002-E01**: 庭のスロットが満杯の状態で植栽を試みる 🟡
  - **入力**: 全スロット使用中に新たな種を植えようとする
  - **期待結果**: 植栽が拒否される
  - **信頼性**: 🟡 *EDGE-002より妥当な推測*

#### 境界値

- [ ] **TC-005-B01**: 放置ターン数が規定の猶予ターン数にちょうど達した場合、枯死する 🔵
  - **入力**: 成熟後、猶予ターン数ちょうどまで放置する
  - **期待結果**: 素材が枯死（全損）する。猶予ターン数-1では枯死しない
  - **信頼性**: 🔵 **確定（2026-07-09）** *EDGE-103「ちょうどで枯死」より*

## REQ-401〜REQ-403: ランク進行・勝敗条件 🟡

**信頼性**: 🟡 **新設（2026-07-09、QAレビューCritical指摘「ランク進行のTCが無い」への対応）** *コンセプト文書3章「ギルドランク」より。ランク区分の正式数・名称はTBD*

### Given（前提条件）
- プレイヤーが特定のランク（ギルドランクHP・制限ターンを持つ）に挑戦中である

### When（実行条件）
- ランクHPが変動する、または制限ターンが経過する

### Then（期待結果）
- ランクHPが0になれば昇格試験へ移行する
- 制限ターン内にHPを0にできなければ降格する

### テストケース

#### 正常系

- [ ] **TC-401-01**: ランクがHPを持つ敵として表現される 🔵
  - **入力**: ランク開始時の状態を確認する
  - **期待結果**: 現在のランクにHP（最大値）が設定されている
  - **信頼性**: 🔵 *REQ-401より*

- [ ] **TC-402-01**: ランクHPが0になると昇格試験へ移行する 🔵
  - **入力**: 貢献度の蓄積によりランクHPを0にする
  - **期待結果**: 昇格試験フェーズへ遷移する
  - **信頼性**: 🔵 *REQ-402より*

- [ ] **TC-403-01**: ランクが定められた進行順序で遷移する 🟡
  - **入力**: 昇格試験クリア後の次ランクを確認する
  - **期待結果**: 定められた順序（例: G→F→E→D→C→B→A→S）で次ランクに進む
  - **信頼性**: 🟡 *REQ-403より。正式なランク区分・数はTBD*

#### 異常系

- [ ] **TC-402-E01**: 制限ターンを使い切ってもランクHPが0にならない場合、降格する 🟡
  - **入力**: 制限ターン終了時点でランクHP>0
  - **期待結果**: 降格処理が行われる（TC-201-E01と同一事象、REQ-206参照）
  - **信頼性**: 🟡 *REQ-206より。降格の具体的な内容（1段階降格か再挑戦か）はTBD*

## REQ-101〜REQ-112, REQ-115: 調合（投入枠・品質・特性発現・品質ペナルティ・系統排他）🔵

**信頼性**: 🔵 *コンセプト文書5章「調合（主戦場）の仕組み」より。2026-07-09のゲームデザイン・Godotアーキテクトレビューを受け、品質ペナルティ(REQ-111)・系統排他(REQ-115)のテストケースを全面改訂*

### Given（前提条件）
- 投入枠が4枠（工房強化後は5枠）存在する
- プレイヤーが品質・特性の異なる素材を複数所持している

### When（実行条件）
- プレイヤーが投入枠に素材を配置し、調合を実行する

### Then（期待結果）
- 完成品の基礎品質が投入素材の平均品質として算出される（REQ-105）
- 同一特性タグを2個以上投入した場合のみ、その特性が完成品に発現する（REQ-106）
- 発現した特性1個につき最終品質が1段階下がる（REQ-111）
- 貢献度系・報酬系が同時に条件を満たす場合、枚数の多い系統のみ発現する（REQ-115）

### テストケース

#### 正常系

- [ ] **TC-101-01**: 品質のみが異なる無特性素材4個を投入する（特性ペナルティなし） 🔵
  - **入力**: 品質 D(1) / C(2) / B(3) / A(4) の無特性素材を各1個ずつ
  - **期待結果**: 発現特性0個のため品質ペナルティなし。最終品質 = 基礎品質 = (1+2+3+4)/4 = 2.5 相当
  - **信頼性**: 🔵 *REQ-105の平均値計算より*

- [ ] **TC-101-02**: 同一特性2個＋無特性2個を投入する（品質ペナルティ1段を確認） 🔵
  - **入力**: 特性「聖」を持つ素材2個（各品質A=4） + 無特性素材2個（各品質A=4）
  - **期待結果**: 基礎品質=4(A)。特性「聖」が発現(REQ-106)し、発現1個分のペナルティで最終品質=3(B)相当に低下する（REQ-111）
  - **信頼性**: 🔵 **改訂（2026-07-09）** *REQ-106, REQ-111より。旧版は品質ペナルティを考慮しておらず不正確だった*

- [ ] **TC-101-03**: 同一特性1個のみを投入する（不発・ペナルティなし） 🔵
  - **入力**: 特性「聖」を持つ素材1個 + 無特性素材3個
  - **期待結果**: 特性「聖」は発現しない（不発）。発現特性0個のためペナルティも発生せず、最終品質=基礎品質のまま
  - **信頼性**: 🔵 *REQ-106「1個では不発」より*

- [ ] **TC-101-04**: 貢献度系・報酬系が同数（2枚 vs 2枚）で条件を満たす場合、両方とも不発 🔵
  - **入力**: 特性「聖」（貢献度系）2個 + 特性「金」（報酬系）2個
  - **期待結果**: REQ-115により両系統とも同数(2vs2)のため不発。発現特性0個につきペナルティも発生しない（品質は特性素材自体の基礎品質の平均のみで決まる）。貢献度・報酬ボーナスは得られない
  - **信頼性**: 🔵 **改訂・確定（2026-07-09）** *REQ-115新設、design-interview.md追補ヒアリングより。旧版は「聖・金の両方が発現する」としており、これがゲームデザインレビューでCritical指摘（貢献度/報酬の二分ジレンマ破壊）を受けた箇所*

- [ ] **TC-101-05**: 貢献度系・報酬系が不均衡（3枚 vs 2枚、投入枠5枠時）の場合、多い方のみ発現 🔵
  - **入力**: 投入枠5枠（工房強化後）に特性「聖」（貢献度系）3個 + 特性「金」（報酬系）2個
  - **期待結果**: REQ-115により貢献度系「聖」（3枚）が報酬系「金」（2枚）より多いため「聖」のみ発現。「金」は不発。発現特性1個分のペナルティが適用される
  - **信頼性**: 🔵 **新設（2026-07-09）** *REQ-115より*

- [ ] **TC-101-06**: 同一系統内で複数特性が同時発現する場合、ペナルティが加算的に積み重なる 🔵
  - **入力**: 投入枠4枠に貢献度系の異なる特性「聖」2個 + 「浄」2個（同一系統内、REQ-112）
  - **期待結果**: 「聖」「浄」の両方が発現（同一系統のためREQ-115の排他対象外）。発現特性2個分のペナルティで最終品質が基礎品質から2段階低下する
  - **信頼性**: 🔵 **新設（2026-07-09、Godotアーキテクトレビュー・ゲームデザインレビュー対応）** *REQ-112, REQ-111より*

- [ ] **TC-101-07**: 1素材が2つの特性タグ（貢献度系+報酬系）を同時に持つ場合でも、品質と特性を無条件に両取りできない 🔵
  - **入力**: 「聖」「金」の両タグを持つ素材2個 + 高品質無特性素材2個
  - **期待結果**: 「聖」（貢献度系）「金」（報酬系）がともに2個ずつの条件を満たすため、REQ-115により両系統とも不発（TC-101-04と同じ同数不発ルール）。無条件に高品質かつ両特性を得る支配戦略は成立しない
  - **信頼性**: 🔵 **新設（2026-07-09、ゲームデザインレビュー「Critical 1: 食い合いが支配戦略を許す」への直接対応）** *REQ-104, REQ-111, REQ-115より*

#### 異常系

- [ ] **TC-101-E01**: 投入枠に素材を1つも入れずに調合を実行する 🟡
  - **入力**: 投入枠が空
  - **期待結果**: 調合が成立せず、エラーまたは実行不可の状態になる
  - **信頼性**: 🟡 *EDGE-001より妥当な推測*

#### 境界値

- [ ] **TC-101-B01**: 同一特性がちょうど2個の場合 🔵
  - **入力**: 特性「癒」2個 + 無特性2個
  - **期待結果**: 「癒」が発現する（境界値として発現側に倒れる）
  - **信頼性**: 🔵 *EDGE-101、REQ-106「2個以上」の明確な境界*

- [ ] **TC-101-B02**: 品質ペナルティにより最終品質がD（スコア1）を下回りそうな場合 🔵
  - **入力**: 基礎品質D(1)相当の素材構成で、特性を1個以上発現させる
  - **期待結果**: 最終品質はD（スコア1）を下限とし、それ以上は下がらない
  - **信頼性**: 🔵 **新設（2026-07-09）** *REQ-111「最終品質はDを下回ってはならない」より*

## REQ-501〜REQ-503: プロトタイプ検証 🔵

**信頼性**: 🔵 *コンセプト文書6章「検証すべき最優先の仮説」より*

### Given（前提条件）
- 品質・特性の異なる素材データが数種類用意されている
- 庭・時間経過はダミー実装（ボタンで素材即時入手）である

### When（実行条件）
- プレイヤー（検証対象者）が1画面プロトタイプで素材を投入枠に配置する

### Then（期待結果）
- 「どの素材を入れるか一瞬迷うか」を観察・記録できる

### テストケース
