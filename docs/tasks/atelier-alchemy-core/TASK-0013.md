## タスク概要

調合の最初のステップである「基礎品質」の算出ロジックを純粋関数として実装する。基礎品質は投入素材の品質値（D〜S、スコア1〜5相当）の平均値であり、REQ-111の品質ペナルティ（TASK-0016）が適用される前の値である。dataflow.md「機能2: 調合」のオーケストレーション5ステップのうち、ステップ1に該当する。

このロジックはシンプルな平均値計算だが、後続のペナルティ適用（TASK-0016）・貢献度/報酬算出（TASK-0017）の起点となる値であり、境界値（品質下限D=1）の扱いを含めTC-101-01で正確性を担保する必要がある。

## 実装詳細

### 1. QualityCalculator.calculate_base_quality 🔵

**信頼性**: 🔵 *REQ-105「システムは完成品の基礎品質を投入素材の平均品質として算出しなければならない」、architecture.mdの関数シグネチャ例より*

投入素材（`Array[MaterialInstance]`）の`quality`値（int換算: D=1〜S=5）の算術平均を返す。architecture.mdの関数シグネチャ例は`-> int`だが、TC-101-01は「(1+2+3+4)/4 = 2.5相当」という非整数の中間値を明示的に期待結果としており、素朴に`int`型で丸めると2.5という値自体を保持できない矛盾がある。この不整合は設計文書間（architecture.mdのシグネチャ例とacceptance-criteria.mdの期待結果）で未解消のため、本タスクでは`calculate_base_quality`の戻り値型を`float`とし、整数への丸め・段階（D〜S）への変換は呼び出し側（TASK-0016のペナルティ適用や表示側）の責務とする方針を採用する。

**実装ファイル**: `features/alchemy/logic/quality_calculator.gd`

```gdscript
# 関数シグネチャ例
class_name QualityCalculator
extends RefCounted

static func calculate_base_quality(materials: Array[MaterialInstance]) -> float:
    pass
```

### 2. 空配列入力時の挙動 🟡

**信頼性**: 🟡 *EDGE-001「投入枠に素材が1つも入っていない状態で調合を実行しようとした場合、システムは調合を成立させてはならない」からの妥当な推測*

EDGE-001の「調合を成立させない」制御自体はオーケストレーター（`AlchemyResolver.craft`、TASK-0018）またはUI（TASK-0020）の責務だが、`calculate_base_quality`が空配列を渡された場合にゼロ除算やクラッシュを起こさないよう防御的に実装する。本関数は`materials`が空の場合`0.0`を返す（呼び出し元が空配列チェックを別途行う前提）。

**実装ファイル**: `features/alchemy/logic/quality_calculator.gd`

## 注意事項

- **設計文書間の不整合に関する申し送り**: architecture.mdの関数シグネチャ例（`calculate_base_quality(materials) -> int`）とacceptance-criteria.md TC-101-01の期待結果（「2.5相当」という非整数値）は厳密には矛盾する。本タスクでは戻り値型を`float`とすることでTC-101-01の期待結果をそのまま満たす方針を採る。TASK-0016（品質ペナルティ）・TASK-0017（貢献度/報酬算出）・CraftResult（TASK-0012、`MaterialInstance.Quality`型=int enum）との間で、どの段階でfloatからQuality enum（D〜S）への変換を行うかを整合させる必要がある。実装時にこの変換ポイントをコードコメントで明示すること。
- 本関数は純粋関数（`static func`のみで構成、Nodeを継承しない）として実装し、GameStateやAutoloadを一切参照しないこと（architecture.md「Functional Core（logic/）」の原則）。
