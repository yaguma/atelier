## 実装詳細

### 1. RngService Autoloadの基本構造 🔵

**信頼性**: 🔵 *architecture.mdのAutoload構成表「TypeScript版の概念 / Godotでの対応」より*

- `Node` を継承したAutoloadシングルトンとして実装する（GameState等と同様の構成。Functional Coreではなく明示的にImperative Shell側に属する）
- 内部で Godot標準の `RandomNumberGenerator` インスタンスを保持し、シード設定・乱数取得の窓口を一本化する
- 「シード管理付き乱数生成（庭の特性抽選等）」という記載の通り、庭Feature（TASK-0002で骨組み作成済み、Phase 2で実装）の特性抽選から呼び出されることを前提としたAPI設計とする

**実装ファイル**: `atelier-godot/autoload/rng_service.gd`

```gdscript
# res://autoload/rng_service.gd
extends Node
# シード管理付き乱数生成Autoload。architecture.md「autoload/rng_service.gd」対応。
# REQ-006: 収穫時の特性乱数は「分散のみで期待値は変えない」ことを保証する基盤。

var _rng: RandomNumberGenerator = RandomNumberGenerator.new()

func _ready() -> void:
	# シード未指定時は起動ごとに非決定的な乱数となるよう、OSの時刻ベースで初期化する
	_rng.randomize()

## シードを明示的に指定して乱数生成器を初期化する。テストの再現性確保に使用する。
func set_seed(seed_value: int) -> void:
	_rng.seed = seed_value

## 現在のシード値を取得する（デバッグ・テスト検証用）
func get_seed() -> int:
	return _rng.seed

## [min_inclusive, max_inclusive] の範囲で一様分布の整数を返す
func next_int(min_inclusive: int, max_inclusive: int) -> int:
	return _rng.randi_range(min_inclusive, max_inclusive)

## 配列から要素を1つ、一様分布でランダムに選択する（REQ-006の特性タグ抽選等に使用）
func pick_one(candidates: Array) -> Variant:
	assert(not candidates.is_empty(), "RngService.pick_one: candidatesが空です")
	var index: int = next_int(0, candidates.size() - 1)
	return candidates[index]
```

| 名前 | パス | Singleton |
|---|---|---|
| `RngService` | `res://autoload/rng_service.gd` | 有効 |

### 3. 「分散のみで期待値を変えない」設計の明確化 🟡

**信頼性**: 🟡 *REQ-006の文言「分散のみで期待値は変えない」から、一様分布APIとして解釈した妥当な推測*

REQ-006は特性抽選が偏り（特定の特性が出やすい重み付け）を持たないことを求めていると解釈し、`pick_one` は候補配列内で常に均等な確率（1/N）で選択する一様分布のみを提供する。重み付き抽選が将来必要になった場合は、本サービスに新規メソッドを追加する形で対応し、既存の `pick_one` の挙動は変更しない（既存呼び出し元への影響を避けるため）。

## 単体テスト要件

### テストケース1: シード指定時の再現性 🔵

**信頼性**: 🔵 *完了条件「同一シードを指定した場合、同一の乱数列が再現される」より*

**Given**: RngServiceに `set_seed(12345)` を実行した状態
**When**: `next_int(1, 100)` を5回連続で呼び出し、結果を配列に記録する
**Then**: 別途 `set_seed(12345)` で再初期化した上で同じ操作を行うと、記録した乱数列と完全に一致する

**テストファイル**: `tests/unit/features/rng_service_test.gd`

### テストケース2: シード未指定時の非決定性 🟡

**信頼性**: 🟡 *完了条件「シード未指定時は非決定的な乱数が得られる」から妥当な推測したテスト設計（乱数の非決定性を厳密に証明することは原理上不可能なため、統計的な妥当性確認とする）*

**Given**: RngServiceを明示的なシード指定なしに使用する状態（`_ready()` 直後）
**When**: 異なる2つのRngServiceインスタンス相当の初期化（またはシード値取得）を行う
**Then**: 取得したシード値が異なる（同一プロセス内で連続初期化しても衝突しない）ことを確認する

**テストファイル**: `tests/unit/features/rng_service_test.gd`

### テストケース3: `pick_one` の一様性（境界値含む） 🔵

**信頼性**: 🔵 *REQ-006「分散のみで期待値は変えない」の要件を検証するテスト設計*

**Given**: 3要素の候補配列 `["A", "B", "C"]` と固定シード
**When**: `pick_one` を1000回呼び出し、各要素の出現回数を集計する
**Then**: 各要素の出現比率が理論値（約33.3%）から大きく外れない（統計的許容範囲内、例えば ±10%以内）こと、かつ配列外の値が一切返らないこと

**テストファイル**: `tests/unit/features/rng_service_test.gd`

### テストケース4: `pick_one` の異常系（空配列） 🔵

**信頼性**: 🔵 *実装詳細の `assert` 記述に対応する異常系テスト*

**Given**: 空の候補配列 `[]`
**When**: `pick_one([])` を呼び出す
**Then**: アサーションエラー（または例外相当の挙動）が発生し、不正な状態のまま処理が継続しない

**テストファイル**: `tests/unit/features/rng_service_test.gd`

### テストケース5: `next_int` の境界値 🔵

**信頼性**: 🔵 *一般的な範囲指定APIの境界値テストとして妥当*

**Given**: `min_inclusive == max_inclusive` となる範囲（例: `next_int(5, 5)`）
**When**: 複数回呼び出す
**Then**: 常に `5` が返る（範囲が1点のみの場合に例外なく動作する）

**テストファイル**: `tests/unit/features/rng_service_test.gd`

## 注意事項

- 本タスクの実行にはTASK-0003（GUT導入）が完了していることが望ましい。依存関係グラフ上の直接の前提タスクはTASK-0002のみだが、GUTテストを実行するにはTASK-0003のテスト基盤が必要なため、実施順序としてはTASK-0003完了後に着手することを推奨する
