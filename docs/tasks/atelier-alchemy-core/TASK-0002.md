## タスク概要

architecture.md「ディレクトリ構造（案）」で定義された、Feature-Based Architectureに基づくディレクトリ構造を `atelier-godot/` 配下に構築する。庭（garden）・調合（alchemy）・ギルド納品（guild）・工房強化（workshop）・プロトタイプ（prototype）の各Featureディレクトリ、共通コード（shared）、シーン（scenes）、テスト（tests）のディレクトリを空またはプレースホルダファイル付きで作成する。本タスクはPhase 1における後続の全実装タスク（TASK-0003〜0006）の配置先を確定させる基盤作業である。

### 2. 空ディレクトリのGit管理対応 🟡

**信頼性**: 🟡 *Gitは空ディレクトリを追跡できないという一般的制約への妥当な対応*

Gitは空ディレクトリをコミットできないため、各末端ディレクトリに `.gitkeep` を配置する。ただし、TASK-0004〜0006で即座にファイルが配置されるディレクトリ（`autoload/`, `shared/constants/`, `shared/theme/`）は `.gitkeep` を省略してよい。

```
# 例: 空のまま残るディレクトリへの対応
features/garden/logic/.gitkeep
features/garden/ui/.gitkeep
features/garden/data/.gitkeep
tests/unit/features/garden/.gitkeep
（他Featureも同様）
```

### 3. `tests/unit/features/` のFeature別サブディレクトリ 🟡

**信頼性**: 🟡 *architecture.mdの `tests/unit/features/` 記載とtesting.mdのFeature単位テスト配置原則から妥当な推測*

architecture.mdは `tests/unit/features/` までしか明記していないが、Feature-Based Architectureの原則（`.claude/rules/architecture.md`のテスト配置パターン）に倣い、`garden/alchemy/guild/workshop` のサブディレクトリを事前に用意する。`prototype/` はロジックを持たないため対象外とする。

**実装ファイル**: `atelier-godot/tests/unit/features/{garden,alchemy,guild,workshop}/`

### 4. `prototype` Featureの簡略構造 🔵

**信頼性**: 🔵 *architecture.mdで `prototype/` が `ui/` のみを持つ構造として明記されている*

`prototype/` はREQ-501〜503（1画面プロトタイプ検証）専用であり、`ui/alchemy_prototype.tscn` のみを配置する構造のため、`logic/` `data/` は作成しない。

**実装ファイル**: `atelier-godot/features/prototype/ui/`
