## タスク概要

調合完成品の「貢献度」（ランクHPへのダメージ）と「報酬」（ゴールド）を算出するロジックを実装する。REQ-109・REQ-110で式の構造（4つの係数の乗算）は確定しているが、各係数の具体値（基礎貢献度・基礎報酬・ボーナス倍率）はバランス調整フェーズで確定させるTBD項目である。本タスクでは式の構造を正しく実装し、係数は`RecipeDefinition`（TASK-0012）・`TraitDefinition.bonus_multiplier`（TASK-0011）・`game_balance.gd`（TASK-0005、他フェーズ）から取得する設計とする。

### 2. 各係数の算出方法 🟡

**信頼性**: 🟡 *REQ-109, REQ-110の各係数について、具体的な算出式が設計文書に明記されていないための実装判断*

- **基礎貢献度/基礎報酬**: `recipe.base_contribution` / `recipe.base_reward`（TASK-0012、RecipeDefinition）をそのまま使用する
- **品質倍率**: 🔴 *最終品質（`MaterialInstance.Quality`, 1〜5）から倍率への変換式は要件定義書・データモデル・データフローのいずれにも明記がなく、完全な推測となる。本タスクでは暫定的に`quality_multiplier = float(final_quality) / float(MaterialInstance.Quality.C)`（品質Cを基準値1.0とする線形倍率）を採用する。この計算式自体がバランス調整フェーズで見直される可能性が高いことを実装者は認識すること*
- **貢献度系/報酬系特性ボーナス**: `activated_traits`のうち該当カテゴリ（貢献度計算ならCONTRIBUTION、報酬計算ならREWARD）に属する特性の`bonus_multiplier`（TASK-0011、TraitDefinition）を全て乗算する。該当特性が0件の場合は`1.0`（ボーナスなし）とする
- **指定合致ボーナス**: `daily_request`の`required_recipe_id`が`recipe.id`と一致する場合に`daily_request.bonus_multiplier`を適用し、一致しない場合は`1.0`とする

**実装ファイル**: `features/alchemy/logic/value_calculator.gd`

## 注意事項

- **設計文書間の重大な不整合（要解消・最重要の申し送り事項）**: REQ-109/110の式は「指定合致ボーナス」を貢献度・報酬の算出に直接含めており、dataflow.md「機能2: 調合」ステップ5も`calculate_contribution`/`calculate_reward`の入力に「指定合致ボーナス」を明記している。一方、dataflow.md「機能3: ギルド納品」の流れでは、`item_crafted`シグナル発火後にguild機能の`DeliveryCalculator.check_daily_request_match()`が**別途**合致ボーナスを算出し、`rank_hp -= 貢献度 × 合致ボーナス` / `gold += 報酬 × 合致ボーナス`という形で**再度**乗算している。architecture.mdのディレクトリ構成でも`guild/logic/delivery_calculator.gd`が「指定合致ボーナス判定」の責務を持つと明記されており、alchemy機能の`ValueCalculator`と責務が重複しているように見える。この設計のままでは合致ボーナスが二重に適用されてしまう可能性が高い。本タスクではREQ-109/110の式をそのまま実装するが、**Phase 4（guild機能）着手前に、合致ボーナスをalchemy側（本タスク）とguild側（delivery_calculator.gd）のどちらか一方でのみ適用するよう設計を確定させる必要がある**。現時点でどちらが正しいかを判断する材料が設計文書内にないため、本注意事項をタスク分割時点の既知の課題として明示的に申し送る。
- 品質倍率の計算式（`float(final_quality) / float(Quality.C)`）は完全な推測（🔴）であり、バランス調整フェーズで別の式（例: 段階的な倍率テーブル）に置き換えられる可能性が高い。実装時にこの部分を差し替えやすいよう、`game_balance.gd`（TASK-0005）に品質倍率テーブルを定数として切り出すことを推奨する。
- 基礎貢献度・基礎報酬・各ボーナス係数はいずれもTBD（requirements.md「未確定数値一覧」参照）。本タスクのテストでは係数の絶対値ではなく、式の乗算構造・系統ごとの独立性を検証することに主眼を置く。
