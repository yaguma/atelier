## タスク概要

庭に植えた種の成熟判定・枯死判定・放置による品質上昇を計算する `GrowthCalculator` を、Functional Core（副作用のない `static func` のみで構成するクラス）として実装する。architecture.mdの方針（「ランク等の外部状態はAutoload参照ではなく必ず引数で受け取る」）に倣い、本クラスも `SeedDefinition` と経過ターン数を引数として受け取るのみで、`GameState` 等のAutoloadを一切参照しない。ユーザストーリー1.2「安全にBで抜くかS狙いで待つか」の判断材料となる、成熟後品質上昇と枯死リスクの境界値ロジックが本タスクの中核である。

## 実装詳細

### 1. 成熟判定 `is_matured` 🔵

**信頼性**: 🔵 *REQ-003「植えた素材ごとに固有の成熟ターン数を管理」、dataflow.md「機能1」シーケンス図の`GC.is_matured(...)`呼び出しより*

```gdscript
# res://features/garden/logic/growth_calculator.gd
class_name GrowthCalculator

static func is_matured(seed_def: SeedDefinition, turns_since_planted: int) -> bool:
	return turns_since_planted >= seed_def.maturity_turns
```

`turns_since_planted` が `maturity_turns` に到達した時点（ちょうどの境界値を含む）で成熟済みとする。dataflow.mdのシーケンス図では引数を `planted_material, current_turn` としているが、Functional Coreの「入力のみに依存」原則（architecture.md）に従い、経過ターン数を明示的な `int` 引数として受け取る形に翻訳する。

**実装ファイル**: `features/garden/logic/growth_calculator.gd`

### 2. 枯死判定 `is_withered` 🔵

**信頼性**: 🔵 **確定（2026-07-09）** *EDGE-103「猶予ターン数ちょうどで枯死。猶予は1ターン追加ではなく、規定ターン数＝境界値そのもの」より*

```gdscript
static func is_withered(seed_def: SeedDefinition, turns_since_maturity: int) -> bool:
	return turns_since_maturity >= seed_def.wither_grace_turns
```

`turns_since_maturity`（成熟後の放置ターン数）が `wither_grace_turns` に**到達した時点**（`>=`、`>` ではない）で枯死とする。EDGE-103により「猶予ターン数-1では枯死しない」（TC-005-B01）ことも同時に保証される境界値実装とする。

**実装ファイル**: `features/garden/logic/growth_calculator.gd`

### 3. 放置による品質上昇 `calculate_quality` 🔵

**信頼性**: 🔵 *REQ-004「成熟後の素材について、収穫せずに放置すると品質が上昇する仕組み」、TC-004-01「品質がB→Aへ上昇する」より*

```gdscript
static func calculate_quality(seed_def: SeedDefinition, turns_since_maturity: int) -> MaterialInstance.Quality:
	var raw_score: int = int(seed_def.base_quality) + turns_since_maturity
	var clamped_score: int = clampi(raw_score, MaterialInstance.Quality.D, MaterialInstance.Quality.S)
	return clamped_score as MaterialInstance.Quality
```

成熟後1ターン経過ごとに品質スコアを1段階ずつ上昇させ、最大 `S`（スコア5）でクランプする。TC-004-01（品質B相当の素材をさらに1ターン放置するとB→Aへ上昇）はこの計算式で `base_quality` がB相当となるよう放置ターン数を調整したケースとして再現される。品質上昇のペース（1ターン=1段階）は具体的な数値がTBDであり、`balance-tuning-cycle`での調整対象とする 🟡。

**実装ファイル**: `features/garden/logic/growth_calculator.gd`

### 4. 収穫可否の統合判定 `can_harvest` 🔵

**信頼性**: 🔵 **確定（2026-07-09）** *EDGE-003「成熟前の素材を収穫しようとした場合、システムは収穫操作自体を許可してはならない」より*

```gdscript
static func can_harvest(seed_def: SeedDefinition, turns_since_planted: int, turns_since_maturity: int) -> bool:
	if not is_matured(seed_def, turns_since_planted):
		return false
	return not is_withered(seed_def, turns_since_maturity)
```

成熟前（`is_matured == false`）は収穫不可（EDGE-003）。枯死済み（`is_withered == true`）の場合も収穫対象として扱わない（枯死＝全損のため、収穫UIではそもそも「収穫」ではなく「除去」等の別操作として扱う想定だが、本関数は「品質を持つ収穫が可能か」の判定に限定する）。

**実装ファイル**: `features/garden/logic/growth_calculator.gd`

**信頼性**: 🔵 *acceptance-criteria.md TC-004-01より*

**Given**: 成熟済み素材（`base_quality` がB相当となるよう `turns_since_maturity` を調整した状態）

## 注意事項

- 本クラスはFunctional Coreの原則（副作用なし、Autoload参照禁止）を厳守する。`GameState.current_turn` 等を直接参照せず、必ず `turns_since_planted` / `turns_since_maturity` を引数で受け取る設計とする

- `can_harvest` は「収穫可能か」の判定のみを行う。枯死した素材のインベントリからの除去処理はGameState側（TASK-0024）のスコープとする
