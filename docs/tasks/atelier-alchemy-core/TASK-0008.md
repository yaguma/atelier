## タスク概要

1画面プロトタイプ（TASK-0009）で使用する、品質（D〜S）と特性タグの異なる素材のダミーマスターデータを作成する。庭・時間経過は本タスクの対象外（REQ-502によりダミー実装で代替するため、プロトタイプでは素材はボタン操作で即時入手する前提）。本タスクは素材の「静的な定義データ」のみを扱い、入手ボタンの実装はTASK-0009で行う。

## 依存タスク

- **前提タスク**: TASK-0005（他フェーズ実施想定。マスターデータ用Resource基盤の存在を前提とするためリンクのみ）
- **後続タスク**: [TASK-0009](TASK-0009.md)

## 完了条件

- [ ] 品質D〜Sの5段階を横断する素材データが用意されている
- [ ] 特性タグ（貢献度系・報酬系それぞれ最低1種類ずつ）を持つ素材が含まれている
- [ ] 特性タグを持たない素材（品質のみで比較できる素材）が最低1種類含まれている
- [ ] 同一特性タグを2個以上投入できる組み合わせが作れる（TC-501-02の閾値発現確認に必要な数量が用意されている）
- [ ] `.tres`リソースまたはGDScriptのコード内定数として、`features/alchemy/data/` または `features/prototype/` 配下に配置されている

## 実装詳細

### 1. ダミー素材データセットの設計 🔵

**信頼性**: 🔵 *REQ-502「庭・時間経過・演出はダミー実装（素材はボタン操作で即時入手）」、REQ-503「品質・特性の異なる複数種の素材を提示」より*

品質D〜S（スコア1〜5相当、REQ-103）と特性タグ0〜2個（REQ-104）の組み合わせを持つ素材を複数種類用意する。TC-501-H01（検証対象者が素材選択時に迷うか）の観察に足る「選ぶ理由が対立する」データセットを意識し、以下の観点を満たす構成とする。

- 品質は高いが特性タグを持たない素材（品質重視の選択肢）
- 品質は低いが特性タグを持つ素材（特性重視の選択肢）
- 貢献度系特性を持つ素材、報酬系特性を持つ素材をそれぞれ用意し、REQ-115の排他制御（両系統同数なら不発）を試せる数量バランスにする
- 同一特性タグを持つ素材を最低2種類（またはボタン操作で同一素材を複数回入手可能な設計であれば1種類でよい）用意し、EDGE-101（閾値ちょうど2個で発現）を再現できるようにする

**実装ファイル**: `features/prototype/data/prototype_material_definitions.gd`（またはTASK-0005で定義済みの`material_definition.gd` Resourceを流用した`.tres`群）

### 2. 素材定義データ構造の踏襲 🟡

**信頼性**: 🟡 *architecture.md「マスターデータ設計」より、TASK-0005で作成される正式なMaterialDefinitionリソースを流用する前提の推測*

TASK-0005で`material_definition.gd`（品質・特性タグを持つResource定義）が存在する場合はそれをそのまま流用し、プロトタイプ専用のダミーインスタンスを`.tres`として複数作成する。TASK-0005が未着手・別スコープの場合は、プロトタイプ専用の簡易データ構造（GDScriptの`const`配列や辞書）で代替してよい（本タスクはプロトタイプ検証が目的であり、正式なマスターデータ基盤の完成を待たない）。

**実装ファイル**: `features/prototype/data/prototype_material_definitions.gd`

## 単体テスト要件 / 動作確認要件

本タスクはDIRECTタスク（データ定義のみ）のため、ユニットテストではなく動作確認要件として記載する。

### 確認項目1: 品質段階の網羅性 🔵

**信頼性**: 🔵 *REQ-503「品質・特性の異なる複数種の素材を提示」より*

**Given**: プロトタイプ用素材データセットが定義されている
**When**: データセット内の品質値を確認する
**Then**: D・C・B・A・Sの5段階すべてが最低1種類の素材でカバーされている

### 確認項目2: 特性タグの組み合わせ確認 🔵

**信頼性**: 🔵 *REQ-104, REQ-106, REQ-107より*

**Given**: プロトタイプ用素材データセットが定義されている
**When**: 特性タグを持つ素材を確認する
**Then**: 貢献度系特性を持つ素材と報酬系特性を持つ素材がそれぞれ存在し、同一特性を2個投入して閾値発現（REQ-106）を試せる数量が確保されている

### 確認項目3: Godotエディタでの読み込み確認 🟡

**信頼性**: 🟡 *Godotの`.tres`リソースの一般的な検証手順からの推測*

**Given**: `.tres`形式で素材データを作成した場合
**When**: Godotエディタでプロジェクトを開く
**Then**: リソースファイルがパースエラーなく読み込める
