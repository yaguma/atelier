## タスク概要

完成品（`CraftResult`）が本日の日替わり指定調合物（`DailyRequest`）に合致するかを判定し、合致ボーナス倍率を返す純粋関数 `DeliveryCalculator.check_daily_request_match()` を実装する。dataflow.md「機能3: ギルド納品（自動）〜ランク判定」のシーケンス図で `GS->>DC: check_daily_request_match(完成品, 本日の指定調合物)` として定義されている処理そのものであり、TASK-0029のGameState納品処理から呼び出されるFunctional Core（`logic/`）として実装する。

## 実装詳細

### 1. DeliveryCalculator（純粋関数）の実装 🔵

**信頼性**: 🔵 *dataflow.md「機能3」のシーケンス図、REQ-204より*

`architecture.md`のFunctional Core方針（`static func` のみで構成、副作用なし、外部状態はAutoload参照ではなく引数で受け取る）に従い、`craft_result` と `daily_request` の2引数のみから合致ボーナス倍率を算出する。

```gdscript
# res://features/guild/logic/delivery_calculator.gd
class_name DeliveryCalculator
extends RefCounted

static func check_daily_request_match(craft_result: CraftResult, daily_request: DailyRequest) -> float:
	if daily_request == null:
		return 1.0
	for trait_def: TraitDefinition in craft_result.activated_traits:
		if trait_def.category == daily_request.preferred_category:
			return daily_request.bonus_multiplier
	return 1.0
```

**実装ファイル**: `features/guild/logic/delivery_calculator.gd`

### 2. 合致判定の対象範囲 🟡

**信頼性**: 🟡 *dataflow.mdのシーケンス図は関数シグネチャのみを定義しており、判定の内部アルゴリズムは明記されていないための妥当な推測*

`DailyRequest` は `required_recipe_id`（要求レシピID）と `preferred_category`（貢献度系/報酬系のどちらを求めるか）の2フィールドを持つが（data-model.md）、acceptance-criteria.md TC-201-02は「本日の指定＝『貢献度系特性を持つ品』、納品物＝貢献度系特性を発現した完成品」という**カテゴリ一致**のみを条件に合致を判定している。`CraftResult`自体はどのレシピで作られたかのIDを保持しないため（data-model.md「調合結果（CraftResult）」参照）、本タスクでは**発現特性のカテゴリ一致のみ**を合致条件とする。`required_recipe_id`によるレシピ単位の合致判定が別途必要になった場合は、`CraftResult`へのレシピID追加を含めて別タスクで再設計する（本タスクのスコープ外）。

**実装ファイル**: `features/guild/logic/delivery_calculator.gd`

## 単体テスト要件

### テストケース1: 日替わり指定調合物のカテゴリに合致した場合ボーナス倍率を返す 🔵

**信頼性**: 🔵 *acceptance-criteria.md TC-201-02より*

**Given**: `daily_request.preferred_category = CONTRIBUTION`、`craft_result.activated_traits` に貢献度系特性を含む
**When**: `DeliveryCalculator.check_daily_request_match(craft_result, daily_request)` を呼ぶ
**Then**: `daily_request.bonus_multiplier`（例: 1.5）が返る

**テストファイル**: `tests/unit/features/guild/delivery_calculator_test.gd`

### テストケース2: カテゴリが一致しない場合はボーナスなし（倍率1.0）を返す 🟡

**信頼性**: 🟡 *REQ-204「合致する場合はボーナスを付与」の対偶として妥当な推測*

**Given**: `daily_request.preferred_category = REWARD`、`craft_result.activated_traits` に貢献度系特性のみを含む（報酬系特性なし）
**When**: `check_daily_request_match(craft_result, daily_request)` を呼ぶ
**Then**: `1.0` が返る（ボーナスなし）

**テストファイル**: `tests/unit/features/guild/delivery_calculator_test.gd`

### テストケース3: 発現特性が0個の完成品は非合致として扱われる 🟡

**信頼性**: 🟡 *REQ-106（特性不発時は完成品に特性が反映されない）とREQ-204の組み合わせから妥当な推測*

**Given**: `craft_result.activated_traits` が空配列（無特性の完成品）
**When**: `check_daily_request_match(craft_result, daily_request)` を呼ぶ
**Then**: `1.0` が返る（ボーナスなし）

**テストファイル**: `tests/unit/features/guild/delivery_calculator_test.gd`

### テストケース4: 同一系統内で複数特性が発現している場合、いずれか1つでも一致すれば合致とみなす 🟡

**信頼性**: 🟡 *REQ-112（同一系統内での複数同時発現）とREQ-204の組み合わせから妥当な推測*

**Given**: `daily_request.preferred_category = CONTRIBUTION`、`craft_result.activated_traits` に貢献度系特性「聖」「浄」の2種類を含む
**When**: `check_daily_request_match(craft_result, daily_request)` を呼ぶ
**Then**: `daily_request.bonus_multiplier` が返る（複数発現していても合致判定は変わらない）

**テストファイル**: `tests/unit/features/guild/delivery_calculator_test.gd`

## 注意事項

- `daily_request.bonus_multiplier`（REQ-204のボーナス倍率）の具体的な数値はTBDであり、balance-tuning-cycleスキル等の後続バランス調整フェーズで確定させる。本タスクのテストではデフォルト値（暫定1.5）をそのまま使用し、数値自体の妥当性は検証範囲に含めない
- `required_recipe_id` によるレシピ単位の合致判定は、`CraftResult`の設計変更（レシピID保持の追加）を伴う可能性があるため、本タスクではスコープ外とし、実装時にコメントで明記すること
- 本関数は純粋関数（Functional Core）であるため、`GameState` や `RngService` 等のAutoloadを参照してはならない
