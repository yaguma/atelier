## タスク概要

段階的開示（Gランクは特性非表示、Eランク以降で貢献度系/報酬系解禁、Dランク以降で特性種類追加）を、UI（`alchemy_bench.tscn`）とFunctional Core（`TraitActivation.resolve_activated_traits()`）の両面で結線する。architecture.md「ユーザビリティ」節が明記する通り、本タスクは**UI側の表示制御とロジック側の発現無効化という二重の安全策**として実装しなければならない。ロジック側は既にPhase 3（TASK-0014想定）で`reveal_level`引数を受け取る設計になっているため、本タスクではその`reveal_level`を実際のランク・UIに正しく結線し、未解禁の特性を持つ種・素材が庭・ショップの選択肢に一切表示されないこと（REQ-124）まで含めて統合する。

## 実装詳細

### 1. reveal_levelのランクからUIへの結線 🔵

**信頼性**: 🔵 *architecture.md「Functional Core」節『呼び出し側（Imperative Shell）が`GameState.current_rank.trait_reveal_level`を読み取って渡す』、data-model.md RankDefinition.trait_reveal_levelより*

`GameState.current_rank.trait_reveal_level`（0=特性なし, 1=貢献度/報酬解禁, 2=種類追加）を`AlchemyBench` UIが購読し、表示内容を切り替える。ロジック側の`GameState.craft()`は既にこの値を`AlchemyResolver.craft()`へ渡す設計（TASK-0014想定）のため、本タスクではUI側の参照経路を新設する。

```gdscript
# res://features/alchemy/ui/alchemy_bench.gd （追記）
func _update_trait_visibility() -> void:
    var reveal_level := GameState.current_rank.trait_reveal_level
    for trait_label in trait_labels:
        trait_label.visible = reveal_level >= 1  # REQ-121: reveal_level=0（Gランク）では非表示
```

**実装ファイル**: `atelier-godot/features/alchemy/ui/alchemy_bench.gd`

### 2. Gランクでの特性非表示（REQ-121, NFR-201） 🔵

**信頼性**: 🔵 *REQ-121「特性を一切発現させず、品質のみで完成品を評価」、NFR-201「Gランク（チュートリアル）において特性を非表示化」より*

`reveal_level = 0`（Gランク）の場合、投入枠内の素材が持つ特性タグ自体をUI上に一切表示しない（アイコン・ツールチップ・数値のいずれも非表示）。完成品の結果表示も品質のみとし、「発現特性: なし」のような特性への言及すら行わない（NFR-201「特性の概念が一切登場しない」ことがTC-NFR-201-01で検証されるため）。

**実装ファイル**: `atelier-godot/features/alchemy/ui/alchemy_bench.gd`, `atelier-godot/features/alchemy/ui/material_slot.gd`

### 3. Eランク以降での貢献度系/報酬系解禁表示（REQ-122） 🔵

**信頼性**: 🔵 *REQ-122「Eランク以降に到達した場合、貢献度系・報酬系特性を解禁」より*

`reveal_level >= 1`になった時点で、特性タグの表示・発現結果（貢献度系/報酬系のカテゴリ表示含む）をUIに表示する。この際、TraitDefinition.category（CONTRIBUTION/REWARD/SUPPORT）に応じたアイコン・色分けを行う（design-guide.mdのカラートークンを使用し、独自色のハードコードは禁止）。

**実装ファイル**: `atelier-godot/features/alchemy/ui/alchemy_bench.gd`

### 4. Dランク以降での特性種類追加表示（REQ-123） 🟡

**信頼性**: 🟡 *REQ-123「特性タグの種類を追加で解禁」より。追加される具体的な特性種類はTBDのため、表示切替機構自体の汎用性を検証する*

`reveal_level = 2`（Dランク以降）になった時点で追加される特性種類も、既存の`reveal_level`ベースの表示切替機構（手順1〜3で実装したもの）がそのまま適用されることを確認する。具体的な新規特性の定義自体は本タスクのスコープ外（マスターデータ追加は別タスクまたは`content-gen-pipeline`スキルの領域）。

**実装ファイル**: `atelier-godot/features/alchemy/ui/alchemy_bench.gd`

### 5. 未解禁特性の種・素材を庭/ショップの選択肢から除外（REQ-124） 🔵

**信頼性**: 🔵 **確定（2026-07-09）** *REQ-124「未解禁の特性を持つ種・素材について、庭での植栽選択肢・ショップでの購入選択肢に一切表示・提供してはならない」、TraitDefinition.min_rank_to_revealより*

## UI/UX要件

### ローディング状態

- ランク到達時の解禁演出（特性が新たに使えるようになったことの通知）は必須要件ではないが、実装する場合は`GameState.upgrades_updated`等の既存signalパターンに倣い、非同期処理を伴わない即時反映とする

### エラー表示

- 未解禁特性の種・素材は「選択肢に表示しない」ことがREQ-124の要件であり、グレーアウト表示や「ロック中」のようなエラー表示は行わない（表示すること自体が特性の存在を示唆してしまうため、NFR-201の「特性の概念が一切登場しない」という意図に反する）

### アクセシビリティ

- Eランク以降での特性タグ表示は、色だけでなくアイコン+テキストの併記で区別する（design-guide.md「明瞭さ」原則）

## 注意事項

- 本タスクは**UI側の表示切替とFunctional Core側の発現無効化という二重の安全策**であることを実装・テストの両方で明示すること（architecture.md「ユーザビリティ」節）。UI側の表示制御のみに依存すると、UIをバイパスした操作（デバッグ経路等）で特性が意図せず発現するリスクがある
- REQ-124（未解禁特性の種・素材は入手自体を防ぐ）とREQ-121〜123（発現の可否）は異なるレイヤーの制御であり、混同しないこと。REQ-124は庭・ショップの「選択肢生成」段階で、REQ-121〜123は「調合結果の算出」段階でそれぞれ独立に制御する
- REQ-123（Dランクで追加される具体的な特性種類）はTBDのため、本タスクでは表示切替機構の汎用性検証に留め、新規特性のマスターデータ追加自体はスコープ外とする
