## 実装詳細

### 1. 日替わり指定調合物の表示 🔵

**信頼性**: 🔵 *REQ-203、ユーザストーリー3.2「ギルドが毎日提示する『求める調合物』を確認し」より*

`GameState.today_request`（`DailyRequest`）を参照し、要求レシピ名・優先カテゴリ（貢献度系/報酬系）をバナー上のラベルに表示する。表示用テキスト整形は純テスト可能な関数として切り出す。

```gdscript
# res://features/guild/ui/daily_request_banner.gd
extends Control

@onready var request_label: Label = %RequestLabel
@onready var hp_bar: ProgressBar = %HpBar
@onready var turn_label: Label = %TurnLabel

func _ready() -> void:
	GameState.guild_delivered.connect(_on_guild_delivered)
	GameState.rank_hp_depleted.connect(_on_rank_hp_depleted)
	GameState.rank_failed.connect(_on_rank_failed)
	refresh()

func refresh() -> void:
	request_label.text = format_request_text(GameState.today_request)
	hp_bar.max_value = GameState.current_rank.max_hp
	hp_bar.value = GameState.rank_hp
	turn_label.text = str(GameState.remaining_turns)

func format_request_text(daily_request: DailyRequest) -> String:
	if daily_request == null:
		return ""
	return "本日の指定: %s" % daily_request.required_recipe_id
```

**実装ファイル**: `features/guild/ui/daily_request_banner.tscn`, `features/guild/ui/daily_request_banner.gd`

### 2. ランクHP・残りターン数の表示更新 🔵

**信頼性**: 🔵 *REQ-401, REQ-205、ユーザストーリー3.3「残りターン数を意識しながら」より*

`guild_delivered` signal（TASK-0029で実装）を購読し、納品のたびにHPバー・ターン数表示を最新化する。UIはビジネスロジックを持たないため、`rank_hp` の増減計算自体は行わず、`GameState` の値をそのまま読み取って表示するのみとする。

```gdscript
# res://features/guild/ui/daily_request_banner.gd （続き）

func _on_guild_delivered(_contribution: float, _reward: float) -> void:
	hp_bar.value = GameState.rank_hp
	turn_label.text = str(GameState.remaining_turns)
```

**実装ファイル**: `features/guild/ui/daily_request_banner.gd`

### 3. 昇格/降格時の画面遷移 🔵

**信頼性**: 🔵 *TASK-0030の`rank_hp_depleted`/`rank_failed` signal、REQ-402, REQ-206より*

`rank_hp_depleted` signal受信時は昇格試験（workshop機能・恒久投資選択画面）への遷移を、`rank_failed` signal受信時は降格処理をそれぞれトリガーする。降格処理の具体的な内容（REQ-206）はTBDのため、本タスクでは遷移トリガーの呼び出し自体を実装対象とし、遷移先画面の内部実装はワークショップ機能（他タスク）に委ねる。

```gdscript
# res://features/guild/ui/daily_request_banner.gd （続き）

func _on_rank_hp_depleted() -> void:
	SceneTransition.go_to_promotion_screen()  # 昇格試験へ（workshop機能へ遷移）

func _on_rank_failed() -> void:
	SceneTransition.go_to_demotion_screen()  # 降格処理（内容はTBD, REQ-206）
```

**実装ファイル**: `features/guild/ui/daily_request_banner.gd`

## UI/UX要件

### ローディング状態

- 本ゲームは外部通信・非同期I/Oを持たないため（dataflow.md「同期処理のみ」より）、日替わり指定調合物・ランクHP・残りターン数はいずれも `GameState` から同期的に即時取得でき、ローディング表示（スピナー等）は不要である 🔵

### エラー表示

- `GameState.today_request` が未設定（`null`）の場合、`format_request_text()` は空文字列を返しバナーを空表示にする（安全策） 🟡 *要件定義に明記のない防御的実装だが、`today_request`が日の開始時に必ず設定される前提（REQ-203）が崩れた場合のフォールバックとして妥当な推測*
- 昇格・降格に伴う画面遷移自体の失敗（シーンロードエラー等）は、Godotの一般的なシーン遷移エラーハンドリングの範囲内で扱い、本タスク独自のエラー処理は設けない 🟡

## 注意事項

- UIコンポーネントは`GameState`の値を読み取って表示するのみとし、ビジネスロジック（貢献度・報酬の計算、ランク判定）を持たない（architecture.md「UIはビジネスロジックを持たない」方針）
- `SceneTransition.go_to_promotion_screen()` / `go_to_demotion_screen()` は本タスクでの新規実装名の想定であり、既存のシーン遷移の仕組み（他フェーズで実装されるメイン画面遷移ロジック）がある場合はそちらに合わせて命名・実装すること
- 降格処理の具体的な内容・遷移先画面（REQ-206）はTBDであり、balance-tuning-cycle等の後続フェーズで確定するまでは仮の遷移処理（例: 確認ダイアログ表示のみ）でよい
- GUTでのUIシーンテストは、`add_child_autofree()`等でシーンツリーに追加した上でsignalを手動発火させ、ラベル・バーの表示更新を検証する方針とする（testing.mdのE2Eではなくユニットテストの範囲で完結させる）
