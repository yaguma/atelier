## タスク概要

庭（仕込み層）における「種」の静的マスターデータを表す `SeedDefinition` リソースクラスを実装する。data-model.mdで定義された `id`, `display_name`, `maturity_turns`, `wither_grace_turns`, `possible_traits`, `base_quality` の6プロパティを持つGodot `Resource` として実装し、以降のPhase 4タスク（GrowthCalculator, TraitRoll, GameState庭状態管理）が参照する土台となる。本タスクはデータ構造の定義とその妥当性検証のみを対象とし、成熟・枯死・特性抽選のロジック自体はTASK-0022, TASK-0023のスコープとする。

## 依存タスク

- **前提タスク**: TASK-0002（Feature-Basedディレクトリ構造構築、他フェーズ実施想定。`features/garden/data/` の配置先確定を前提とするためリンクのみ）
- **後続タスク**: [TASK-0022: GrowthCalculator（成熟/枯死判定）実装](TASK-0022.md), [TASK-0023: TraitRoll（特性乱数付与）実装](TASK-0023.md)

## 完了条件

- [ ] `SeedDefinition` が `Resource` を継承し、`class_name` を持つ
- [ ] `id: StringName`, `display_name: String`, `maturity_turns: int`, `wither_grace_turns: int`, `possible_traits: Array[StringName]`, `base_quality: MaterialInstance.Quality` の6プロパティが `@export` で定義されている
- [ ] `maturity_turns` のデフォルト値が3、`wither_grace_turns` のデフォルト値が1である（data-model.mdの記載値、具体値はTBDだがデフォルトとしてこの値を採用）
- [ ] `.tres` リソースとしてGodotエディタから編集可能である（インスペクタでエラーなく表示される）

## 実装詳細

### 1. SeedDefinitionリソースクラスの実装 🔵

**信頼性**: 🔵 *data-model.md「種の定義（SeedDefinition）」の記載をそのまま適用*

```gdscript
# res://features/garden/data/seed_definition.gd
class_name SeedDefinition
extends Resource

@export var id: StringName                # 🔵
@export var display_name: String          # 🔵
@export var maturity_turns: int = 3       # 🔵 REQ-003「素材ごとに固有の成熟ターン数」。具体値はTBD
@export var wither_grace_turns: int = 1   # 🔵 成熟後、枯死するまでの猶予ターン数。EDGE-103: 放置ターン数がこの値にちょうど達した時点で枯死
@export var possible_traits: Array[StringName] = []
	# 🔵 REQ-006「収穫時に特性が1つ乱数で付与」。分散のみで期待値は変えない候補一覧
@export var base_quality: MaterialInstance.Quality = MaterialInstance.Quality.C
	# 🟡 放置ターン数に応じて品質が上昇する際の基準値。REQ-004より妥当な推測
```

**実装ファイル**: `features/garden/data/seed_definition.gd`

### 2. `MaterialInstance.Quality` enumへの依存 🟡

**信頼性**: 🟡 *data-model.md「素材インスタンス（MaterialInstance）」との整合性から妥当な推測。MaterialInstanceはalchemy Featureのdata配下（`features/alchemy/data/material_instance.gd`）に実装される想定であり、本タスクの直接のスコープ外*

`base_quality` の型は `features/alchemy/data/material_instance.gd` で定義される `MaterialInstance.Quality` enum（`D=1, C=2, B=3, A=4, S=5`）を参照する。本タスク実施時点で `MaterialInstance` が未実装の場合は、実装順序の都合上、先に最小限の enum 定義のみを持つスタブとして `MaterialInstance` を用意するか、Phase 3（調合コア）側の実装を待ってから本タスクに着手する。依存関係の詳細はチームで別途調整すること。

**実装ファイル**: `features/garden/data/seed_definition.gd`（`MaterialInstance` への型参照のみ）

### 3. 早熟種・晩成種のサンプルデータ準備 🟡

**信頼性**: 🟡 *REQ-003「例: 早熟＝薬草、晩成＝希少鉱石」より妥当な推測*

単体テストおよび後続タスクでの動作確認に使えるよう、`maturity_turns` の異なる最低2種類のサンプル `.tres` インスタンス（例: 早熟種 `maturity_turns=1`、晩成種 `maturity_turns=5`）を用意する。これらはプレースホルダデータであり、正式なマスターデータ（コンテンツ生成フェーズ）とは独立して調整してよい。

**実装ファイル**: `features/garden/data/seeds/sample_early_seed.tres`, `features/garden/data/seeds/sample_late_seed.tres`

## 単体テスト要件

### テストケース1: SeedDefinitionのプロパティが正しく初期化される 🔵

**信頼性**: 🔵 *data-model.mdの型定義・デフォルト値より*

**Given**: 新規に `SeedDefinition` インスタンスを生成する
**When**: 各プロパティにデフォルト値以外の値（`id`, `display_name`, `maturity_turns`, `wither_grace_turns`, `possible_traits`, `base_quality`）を設定する
**Then**: 設定した値がそれぞれ正しく取得できる

**テストファイル**: `tests/unit/features/garden/seed_definition_test.gd`

### テストケース2: デフォルト値が仕様通りである 🔵

**信頼性**: 🔵 *data-model.md記載のデフォルト値（`maturity_turns=3`, `wither_grace_turns=1`, `base_quality=C`）より*

**Given**: プロパティを一切設定しない新規 `SeedDefinition` インスタンス
**When**: 各プロパティを参照する
**Then**: `maturity_turns == 3`, `wither_grace_turns == 1`, `base_quality == MaterialInstance.Quality.C`, `possible_traits` が空配列である

**テストファイル**: `tests/unit/features/garden/seed_definition_test.gd`

### テストケース3: 複数インスタンス間でプロパティが独立している 🟡

**信頼性**: 🟡 *Godot Resourceの参照共有に関する既知の注意点（`@export`配列がデフォルトで共有されうる）から妥当な推測*

**Given**: 2つの `SeedDefinition` インスタンスを生成する
**When**: 一方の `possible_traits` に要素を追加する
**Then**: もう一方の `possible_traits` は影響を受けず空のままである（Resourceのデフォルト値共有バグを防止する回帰テスト）

**テストファイル**: `tests/unit/features/garden/seed_definition_test.gd`

## 注意事項

- 本タスクはデータ構造の定義のみを対象とし、成熟判定・枯死判定・特性抽選のロジックは実装しない（TASK-0022, TASK-0023のスコープ）
- `maturity_turns`, `wither_grace_turns`, `base_quality` の具体的なゲームバランス値はTBD（`docs/spec/atelier-alchemy-core/requirements.md`「未確定数値一覧」参照）であり、本タスクではデータモデルの正しさのみを検証し、バランス調整は後続の`balance-tuning-cycle`スキルで行う
- `possible_traits` の要素（`StringName`）は `TraitDefinition.id` を指す文字列参照であり、本タスク単体では `TraitDefinition` の実体との整合性検証は行わない（結合検証はPhase 3のalchemy実装と合流した段階で行う）
