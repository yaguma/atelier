## タスク概要

「いかなる購入によってもランクの残りターン数を延長できない」（REQ-303）という、v7.0コンセプトの設計上の核心制約を保証・検証する。この要件は「機能を実装する」タスクではなく「機能を実装しない（意図的な除外）」タスクである点が他のPhase 6タスクと性質が異なる。実装としては、TASK-0033で定義した`UpgradeDefinition`の登録一覧全体にターン延長系の項目が存在しないことを機械的に保証するテストと、TASK-0034（恒久投資）・TASK-0035（消耗投資）の購入APIがいかなる`item_id`・`upgrade_id`を渡されても`remaining_turns`を変化させないことを確認する回帰テストを実装する。

## 実装詳細

### 1. UpgradeDefinition一覧にターン延長系項目が存在しないことの保証テスト 🔵

**信頼性**: 🔵 *REQ-303「いかなる購入によってもランクの残りターン数を延長できない」、TC-301-E01「そのような購入項目自体が存在しない」より*

TASK-0034・TASK-0035で登録される全`UpgradeDefinition`の`id`一覧を走査し、ターン延長を示唆する語句（例: `turn`, `extend`, `remaining_turns`等）を含む項目が存在しないことを検証する。これは実装ロジックのテストというより「今後の追加実装が誤ってターン延長系項目を混入させることを防ぐ回帰テスト」としての性格を持つ。

```gdscript
# res://tests/unit/features/workshop/turn_extension_guard_test.gd
extends GutTest

func test_no_turn_extension_items_in_permanent_definitions() -> void:
    var defs := UpgradeCostTable.get_permanent_definitions()
    for def in defs:
        assert_does_not_have_string(str(def.id).to_lower(), "turn")
        assert_does_not_have_string(str(def.id).to_lower(), "extend")

func test_no_turn_extension_items_in_consumable_definitions() -> void:
    var defs := ConsumableCostTable.get_consumable_definitions()  # TASK-0035で定義
    for def in defs:
        assert_does_not_have_string(str(def.id).to_lower(), "turn")
        assert_does_not_have_string(str(def.id).to_lower(), "extend")
```

**実装ファイル**: `atelier-godot/tests/unit/features/workshop/turn_extension_guard_test.gd`

### 2. 購入APIが remaining_turns を変化させないことの網羅的検証 🔵

**信頼性**: 🔵 *REQ-303、dataflow.md「機能4: 工房強化」シーケンス図の注記「ターン延長に相当する購入項目は存在しない(REQ-303)」より*

TASK-0034の`purchase_permanent_upgrade()`、TASK-0035の`purchase_consumable()`について、登録済みの全項目を1つずつ購入した際に`remaining_turns`が呼び出し前後で不変であることをパラメタライズドテスト（`it.each`相当のGUTパターン）で検証する。

**実装ファイル**: `atelier-godot/tests/unit/features/workshop/turn_extension_guard_test.gd`

### 3. remaining_turns変更APIの棚卸し（コードレビュー観点） 🟡

**信頼性**: 🟡 *REQ-303の意図を実装レベルで担保するための妥当な追加検証。設計文書に明記された具体的な検証方法ではないため🟡*

`GameState`内で`remaining_turns`へ代入・加算を行っている箇所をコードレビューし、日進行処理（`advance_day()`相当）以外からの変更経路が存在しないことを確認する。新たな変更経路が見つかった場合はTASK-0038以降で修正する。

**実装ファイル**: なし（コードレビューのみ。結果は本タスクの「注意事項」節に記録）

## 単体テスト要件（TDDタスク）

### テストケース1: ターン延長の購入を試みる（TC-301-E01） 🔵

**信頼性**: 🔵 *acceptance-criteria.md TC-301-E01より*

**Given**: 恒久投資画面・消耗投資ショップの全選択肢一覧
**When**: 「ターン延長」に相当する項目を探す
**Then**: そのような購入項目自体が存在しない（`UpgradeDefinition`一覧のいずれの`id`にも該当しない）

### テストケース2: 恒久投資の購入前後でremaining_turnsが不変 🔵

**信頼性**: 🔵 *REQ-303より*

**Given**: `remaining_turns = N`、恒久投資画面が有効、ゴールド十分
**When**: 登録済みの各恒久投資項目を順に購入する
**Then**: いずれの購入後も `remaining_turns` は `N` のまま変化しない

### テストケース3: 消耗投資の購入前後でremaining_turnsが不変 🔵

**信頼性**: 🔵 *REQ-303より*

**Given**: `remaining_turns = N`、通常ターン中、ゴールド十分
**When**: 登録済みの各消耗投資項目を順に購入する
**Then**: いずれの購入後も `remaining_turns` は `N` のまま変化しない

### テストケース4: 日進行（advance_day）以外はremaining_turnsを変更しない 🟡

**信頼性**: 🟡 *REQ-303の意図をコード構造レベルで担保する追加検証*

**Given**: `GameState`の公開メソッド一覧
**When**: `remaining_turns`を変更するメソッドを洗い出す
**Then**: `advance_day()`（日進行）以外に該当するメソッドが存在しない

## 注意事項

- **REQ-303は「意図的な除外」という設計上の核心制約である**。コンセプト文書6章「金でターンを延長できない（意図的な除外）」が明記する通り、これは実装漏れではなく「今削るか、投資して後で速く削るか」という真剣な賭けの感覚（ユーザストーリー4.3）を成立させるための意図的なゲームデザイン上の制限であり、将来的にも実装してはならない
- 本タスクは新機能を追加するのではなく、TASK-0033〜0035で作られた登録一覧・購入APIに対する「ネガティブテスト（存在しないことの証明）」が主目的である。そのため実装ファイルよりもテストファイルの比重が大きい
- 今後Phase 6以降で工房強化項目が追加される場合（本要件定義のスコープ外の将来拡張）は、必ず本タスクのガードテスト（`turn_extension_guard_test.gd`）に新項目を追加し、ターン延長系でないことを機械的に確認すること
