## タスク概要

architecture.md「システム構成図」の通り、庭（Garden）・調合（Alchemy）・工房強化（Workshop）への導線を持つメイン画面 `scenes/main.tscn` を実装する。本タスクは新規ロジックを実装するのではなく、既存の各Feature UIシーン（`garden_panel.tscn`, `alchemy_bench.tscn`, `daily_request_banner.tscn`, `permanent_upgrade_screen.tscn`, `consumable_shop_panel.tscn`）を単一のメインシーンにコンテナとして統合し、`GameState`のsignal（`rank_hp_depleted`, `rank_failed`, `upgrades_updated`等）を購読してシーン間・画面間遷移を制御する「結線タスク」である。dataflow.md「システム全体のデータフロー（1ターンの流れ）」のフローチャートが、実際の画面遷移として体験できる状態を作る。

## 実装詳細

### 1. main.tscnのコンテナ構成 🟡

**信頼性**: 🟡 *architecture.md「システム構成図」`Main[main.tscn 工房画面]`が`Garden`/`Alchemy`/`Workshop`への矢印を持つことから妥当な推測。具体的なUIレイアウト（タブ切替かパネル切替か）はarchitecture.mdに明記がないため🟡*

各Feature UIシーンを子ノードとしてインスタンス化し、`TabContainer`または独自のパネル切替コンポーネントで表示を切り替える。

```
scenes/main.tscn
├── GardenPanelContainer（features/garden/ui/garden_panel.tscn）
├── AlchemyBenchContainer（features/alchemy/ui/alchemy_bench.tscn）
├── DailyRequestBanner（features/guild/ui/daily_request_banner.tscn）
├── ConsumableShopPanel（features/workshop/ui/consumable_shop_panel.tscn、オーバーレイ表示）
└── PermanentUpgradeScreen（features/workshop/ui/permanent_upgrade_screen.tscn、遷移時のみ表示）
```

**実装ファイル**: `atelier-godot/scenes/main.tscn`, `atelier-godot/scenes/main.gd`

### 2. ランクHP0到達時の画面遷移（昇格試験〜工房強化） 🔵

**信頼性**: 🔵 *dataflow.md「機能3: ギルド納品」シーケンス図`alt rank_hp <= 0: GS-->>UI: signal rank_hp_depleted`、「システム全体のデータフロー」`O -->|Yes| P[昇格試験へ / workshop: 恒久投資選択]`より*

`main.gd`が`GameState.rank_hp_depleted`をsubscribeし、発火時に通常のメイン画面（庭・調合）を非表示にして`PermanentUpgradeScreen`を表示する。TASK-0034で実装した`is_permanent_upgrade_screen_active`フラグの切り替えもこのタイミングで行う。

```gdscript
# res://scenes/main.gd
func _ready() -> void:
    GameState.rank_hp_depleted.connect(_on_rank_hp_depleted)
    GameState.rank_failed.connect(_on_rank_failed)
    GameState.upgrades_updated.connect(_on_upgrades_updated)

func _on_rank_hp_depleted() -> void:
    GameState.is_permanent_upgrade_screen_active = true
    _show_screen(permanent_upgrade_screen)

func _on_upgrades_updated() -> void:
    # 恒久投資の購入完了操作（画面上の「次のランクへ進む」等の確定操作）を受けて
    # is_permanent_upgrade_screen_active を false に戻し、通常メイン画面へ復帰する
    ...
```

**実装ファイル**: `atelier-godot/scenes/main.gd`

### 3. 消耗投資ショップの常時アクセス導線 🔵

**信頼性**: 🔵 *REQ-305「消耗投資の購入をターン中いつでも許可」より*

`ConsumableShopPanel`を通常メイン画面上に常設ボタンとして配置し、庭操作・調合操作のいずれの最中でもオーバーレイ表示で開閉できるようにする。恒久投資画面（ランク間限定）とは異なり、通常メイン画面から独立して呼び出せる導線とする。

**実装ファイル**: `atelier-godot/scenes/main.tscn`, `atelier-godot/scenes/main.gd`

### 4. 降格処理時の画面遷移 🟡

**信頼性**: 🟡 *REQ-206「降格処理を行わなければならない」より。降格の具体的なペナルティ内容・画面演出はTBD（未確定数値一覧参照）のため、遷移の枠組みのみを実装*

`GameState.rank_failed`を購読し、降格が発生したことをプレイヤーに通知した上で通常メイン画面へ復帰させる。降格の具体的なペナルティ内容（ランクHPリセット幅等）は他フェーズ（TASK-0031想定）の実装に依存するため、本タスクでは画面遷移のみを扱う。

**実装ファイル**: `atelier-godot/scenes/main.gd`

## 単体テスト要件（TDDタスク）

### テストケース1: ランクHP0到達で恒久投資画面へ自動遷移する 🔵

**信頼性**: 🔵 *dataflow.md「機能3: ギルド納品」`rank_hp_depleted`シーケンスより*

**Given**: 通常メイン画面が表示されている状態
**When**: `GameState.rank_hp_depleted`signalが発火する
**Then**: `main.gd`が`PermanentUpgradeScreen`を表示し、通常メイン画面（庭・調合）が非表示になる

### テストケース2: 恒久投資選択完了後、次ランクの通常画面へ復帰する 🔵

**信頼性**: 🔵 *ユーザストーリー4.1「所持ゴールドと相談しながら購入する」の完了後、通常プレイに戻るという暗黙の前提、dataflow.md全体フローより*

**Given**: `PermanentUpgradeScreen`が表示されている状態
**When**: 恒久投資の選択（または「選択せず進む」の確定操作）が完了する
**Then**: `is_permanent_upgrade_screen_active`が`false`に戻り、通常メイン画面（庭・調合）が再表示される

### テストケース3: 消耗投資ショップが通常ターン中いつでも開閉できる 🔵

**信頼性**: 🔵 *REQ-305より*

**Given**: 庭操作中または調合操作中の通常メイン画面
**When**: 消耗投資ショップの常設ボタンを押す
**Then**: `ConsumableShopPanel`がオーバーレイ表示され、背後の庭・調合の状態は保持されたままになる

### テストケース4: 1ターンの流れが画面遷移として一巡する（統合的な結線確認） 🟡

**信頼性**: 🟡 *dataflow.md「システム全体のデータフロー（1ターンの流れ）」フローチャート全体の統合確認のため🟡（個別のsignal結線は🔵だが、全体を通した統合テストの記述は設計文書に直接の記載がない）*

**Given**: 通常メイン画面、庭にスロットの空きがあり、在庫に調合可能な素材がある
**When**: 庭で収穫→調合ベンチで調合実行→（`GameState.craft()`経由で）自動納品→ランクHP減算までを順に操作する
**Then**: 各ステップの画面遷移・signal発火が想定通りに連鎖し、最終的に納品結果がUIに反映される

## UI/UX要件

### ローディング状態

- 画面遷移はローカル完結の同期処理のため、非同期ローディング表示は不要。ただし遷移時のフェード等の軽微な演出はTHEME/design-tokensの範囲内で許容する

### エラー表示

- `rank_hp_depleted`と`rank_failed`が万一同時に発火するような不整合な状態遷移が発生した場合、`main.gd`は`rank_hp_depleted`（昇格）を優先し、`rank_failed`（降格）のsignalを無視する（EDGE-104「制限ターンちょうどでランクHPが0になった場合、間に合ったものとみなし昇格試験へ移行」との整合を画面遷移レベルでも担保する）

### アクセシビリティ

- 現在どの画面（庭／調合／工房強化）を操作しているかを常時視認できるインジケータをmain.tscnに配置する（design-guide.mdの「明瞭さ」原則、フェーズごとのアクセントカラーを用いる）

## 注意事項

- `main.tscn`および`main.gd`はarchitecture.md「Imperative Shell」の原則に従い、各Feature UIシーンの表示切替とsignal購読のみを行い、品質計算・貢献度計算等のビジネスロジックを一切持たないこと
- 本タスクは実質的に「結線」タスクであり、TASK-0020, 0025, 0032, 0034, 0035, 0037で実装済みの各UIシーンが揃っていることが前提となる。それらのタスクが未完了の場合、本タスクはモック/スタブのシーンを用いて画面遷移ロジックのみを先行実装してもよい
- EDGE-104（制限ターンちょうどでランクHPが0の場合は昇格を優先し降格処理を行わない）との整合を、画面遷移レベルでも矛盾なく扱うこと
