## タスク概要

調合レシピの静的定義`RecipeDefinition`と、`AlchemyResolver.craft()`（TASK-0018）の戻り値型`CraftResult`を実装する。

`CraftResult`はゲームデザインレビュー・Godotアーキテクトレビューを経て2026-07-09に新設された型で、品質ペナルティ適用前後の値（`base_quality`/`final_quality`）と、系統排他制御（REQ-115）でどちらの系統が不発になったか（`rejected_category`）を明示的に保持する。これにより、TASK-0013〜0017の各純粋関数の計算過程がブラックボックス化せず、UI側（TASK-0020）が「なぜこの結果になったか」を提示できる設計になっている。

## 実装詳細

### 1. RecipeDefinition（レシピ定義） 🔵

**信頼性**: 🔵 *data-model.md「レシピ定義（RecipeDefinition）」より*

REQ-101（投入枠4枠が初期値）、REQ-102（工房強化で+1、最大5枠）を満たすResourceクラスとして実装する。`slot_count`はレシピの基本値であり、工房強化による加算はGameState側（TASK-0019）の責務とする（data-model.mdの明記通り）。

**実装ファイル**: `features/alchemy/data/recipe_definition.gd`

```gdscript
# 型定義（data-model.mdより引用）
class_name RecipeDefinition
extends Resource

@export var id: StringName
@export var display_name: String
@export var slot_count: int = 4          # REQ-101。工房強化による+1加算はGameState側の責務
@export var base_contribution: float = 0.0  # REQ-109の基礎貢献度。具体値TBD
@export var base_reward: float = 0.0        # REQ-110の基礎報酬。具体値TBD
```

### 2. CraftResult（調合結果） 🔵

**信頼性**: 🔵 *data-model.md「調合結果（CraftResult）」より。2026-07-09新設*

`AlchemyResolver.craft()`（TASK-0018）の戻り値型。品質ペナルティ適用前後の値、系統排他制御の結果、最終的な貢献度・報酬を1つの構造体にまとめる。RefCountedとする理由はMaterialInstanceと同様、実行時ごとに生成される値オブジェクトのため。

**実装ファイル**: `features/alchemy/data/craft_result.gd`

```gdscript
# 型定義（data-model.mdより引用）
class_name CraftResult
extends RefCounted

var base_quality: MaterialInstance.Quality      # REQ-105。ペナルティ適用前
var final_quality: MaterialInstance.Quality     # REQ-111。品質ペナルティ・触媒補正適用後（下限D=1）
var activated_traits: Array[TraitDefinition] = []
    # REQ-106, REQ-112。同一系統内の複数同時発現を含む、最終的に発現した特性一覧
var rejected_category: TraitDefinition.Category
    # REQ-115。貢献度系/報酬系が同時に条件を満たした場合に不発とされた側（不発なしの場合は無効値）
var contribution: float = 0.0   # REQ-109
var reward: float = 0.0         # REQ-110
```

### 3. `rejected_category`の「無効値」表現について 🟡

**信頼性**: 🟡 *data-model.mdは「不発なしの場合は無効値」と記載するのみで具体的な表現方法は未定義*

GDScriptのenumには`null`相当の値がないため、「不発なし」を表す無効値の表現方法を決定する必要がある。以下のいずれかを採用する（TASK-0015実装時に確定）。

- 案A: `TraitDefinition.Category`に`Category.NONE`を追加する（TraitDefinitionの定義変更が必要なためTASK-0011に影響する可能性がある点に注意）
- 案B: `CraftResult`に`has_rejected_category: bool`を別途持たせ、`rejected_category`自体は無視する

本タスクではCraftResultの型定義自体はdata-model.md記載のまま実装し、無効値表現の最終決定と実装はTASK-0015（`resolve_category_conflict`）で行う。

**実装ファイル**: `features/alchemy/data/craft_result.gd`

## 注意事項

- `CraftResult`は2026-07-09の複数レビュー（ゲームデザインレビュー・Godotアーキテクトレビュー）を経て新設された型である。旧設計では`AlchemyResolver`相当の処理が最終品質・発現特性を戻り値として明示的に返さず、UIが個別の計算関数を直接呼び出していたため、「なぜこの結果になったか」の説明可能性が低く、また支配戦略の温床（REQ-111改訂の経緯）にもなっていた。本データモデルはその反省を踏まえた設計であることを実装者は理解した上で、フィールドの削減・簡略化を行わないこと。
- `rejected_category`の無効値表現は本タスクでは確定させず、TASK-0015の実装判断に委ねる（上記「実装詳細3」参照）。TASK-0012時点では型定義のみを固定し、無効値の具体的な扱いに依存するテストケースは書かない。
- `base_contribution`/`base_reward`はTBD値のため、本タスクのテストでは具体的な数値の妥当性（バランス上の適切さ）は検証しない。数値確定は`balance-tuning-cycle`等の後続フェーズで行う。
