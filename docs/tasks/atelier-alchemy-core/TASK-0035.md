## タスク概要

消耗投資（触媒の常備・購入、種の指名買い）の購入ロジックと、それを提示する `ConsumableShopPanel` を実装する。消耗投資は恒久投資と異なり「ターン中いつでも購入可能」（REQ-305）であり、効果は「該当ターン・該当調合でのみ」（REQ-302）発揮される点が核心の設計制約となる。dataflow.md「機能4: 工房強化」シーケンス図の `purchase_consumable(item_id)` フローをGameState Autoloadに実装する。

## 実装詳細

### 1. GameState.purchase_consumable() 🔵

**信頼性**: 🔵 *dataflow.md「機能4: 工房強化」シーケンス図の `purchase_consumable(item_id)` フローより*

```gdscript
# res://autoload/game_state.gd （追記）
func purchase_consumable(item_id: StringName) -> bool:
    var def := _find_consumable_definition(item_id)  # UpgradeDefinition.Kind.CONSUMABLEのみ検索
    if def == null or gold < def.price:
        return false
    gold -= def.price
    inventory.append(_instantiate_consumable_item(def))  # 触媒はMaterialInstance相当、種の指名買いはSeedDefinition相当に変換
    inventory_updated.emit()
    return true
```

REQ-305「ターン中いつでも許可」に従い、`GameState.purchase_permanent_upgrade()`（TASK-0034）とは異なり文脈フラグ（`is_permanent_upgrade_screen_active`等）による制限を一切設けない。

**実装ファイル**: `atelier-godot/autoload/game_state.gd`

### 2. 触媒（catalyst）の効果適用範囲 🔵

**信頼性**: 🔵 *REQ-108「補助系特性（例: 触媒＝品質+1段）」、REQ-302「該当ターン・該当調合でのみ効果を発揮」より*

購入した触媒は在庫（`inventory`）に通常の `MaterialInstance` 相当として追加され、投入枠に配置された調合でのみ品質+1段の効果を発揮する（REQ-108の補助系特性としての扱いはAlchemyResolver側、Phase 3実装済み想定）。触媒自体に「恒久的にボーナスを与える」設定は行わない。

**実装ファイル**: `atelier-godot/autoload/game_state.gd`

### 3. 種の指名買い（seed_pick）の効果適用範囲 🔵

**信頼性**: 🔵 *REQ-008「調合で必要な特性から逆算して、狙った特性を仕込みやすくする種の選択・購入手段（注文生産）」、REQ-302より*

種の指名買いは、庭のスロットに植える種を狙って購入できる消耗投資。購入した種は庭の空きスロットへ植える対象として在庫に加わるのみで、通常の庭運用（成熟・収穫・特性乱数付与）と同じフローに合流する。恒久的な庭拡張（`garden_expand`、TASK-0034）とは明確に別物として扱う。

**実装ファイル**: `atelier-godot/autoload/game_state.gd`

### 4. consumable_shop_panel.tscn（ターン中ショップUI） 🔵

**信頼性**: 🔵 *REQ-305「ターン中いつでも購入可能」、ユーザストーリー4.2「調合中に触媒が切れていることに気づき、その場でショップから購入する」より*

通常ターン中いつでも開閉可能なパネルとして実装する。恒久投資画面（`permanent_upgrade_screen.tscn`）とは別シーンとし、両者を混同しないUIレイアウトにする（design-guide.mdのカード・ボタンスタイル統一ルールに従う）。

**実装ファイル**: `atelier-godot/features/workshop/ui/consumable_shop_panel.tscn`, `consumable_shop_panel.gd`

## 単体テスト要件（TDDタスク）

### テストケース1: ターン中に触媒を購入する（TC-301-02） 🔵

**信頼性**: 🔵 *acceptance-criteria.md TC-301-02より*

**Given**: 通常ターン中、所持ゴールドが触媒の価格以上
**When**: `GameState.purchase_consumable(&"catalyst")` を呼ぶ
**Then**: 購入が成立し、`gold`が減算され、購入した触媒が`inventory`に追加され、そのターン内の調合（投入枠への配置）で即座に使用可能になる

### テストケース2: 消耗投資は恒久化しない 🔵

**信頼性**: 🔵 *REQ-302「該当ターン・該当調合でのみ効果を発揮」より*

**Given**: 触媒を購入済みの状態
**When**: `GameState.permanent_upgrades` を確認する
**Then**: 触媒のIDが`permanent_upgrades`配列に含まれない（恒久投資と混同されていない）

### テストケース3: 種の指名買いで狙った種を入手する 🔵

**信頼性**: 🔵 *REQ-008, REQ-302より*

**Given**: 通常ターン中、所持ゴールドが指名買いの種の価格以上
**When**: `GameState.purchase_consumable(&"seed_pick")` を呼ぶ（対象の種IDを指定）
**Then**: 指定した種が庭に植える対象として在庫に追加される

### テストケース4: ランク間強化画面の文脈でも消耗投資が拒否されない 🟡

**信頼性**: 🟡 *REQ-305「ターン中いつでも」からの妥当な拡張。恒久投資（TASK-0034）が文脈フラグで制限されるのとの対比を明示的に検証*

**Given**: `is_permanent_upgrade_screen_active = true`（ランク間強化画面中）、所持ゴールドが十分
**When**: `GameState.purchase_consumable(&"catalyst")` を呼ぶ
**Then**: 恒久投資用のフラグに影響されず購入が成立する

### テストケース5: ゴールド不足時の購入拒否 🟡

**信頼性**: 🟡 *REQ-302, REQ-305からの妥当な拡張（一般的な購入ロジックの前提条件）*

**Given**: 所持ゴールドが価格未満
**When**: `GameState.purchase_consumable(item_id)` を呼ぶ
**Then**: 購入が拒否され、`gold`・`inventory`のいずれも変化しない

## UI/UX要件

### ローディング状態

- 消耗投資も同期処理のみ（NFR-101）のため、非同期ローディング表示は不要

### エラー表示

- ゴールド不足の項目は購入ボタンを非活性化する（恒久投資画面TASK-0034と共通のスタイル方針）

### アクセシビリティ

- 触媒と種の指名買いはアイコンで視覚的に区別し、購入後に即座に投入枠へ使用できることが分かるようにトースト等の軽量なフィードバックを表示する（過度な演出は避け、design-guide.mdのボタンスタイルの範囲内で実装する）

## 注意事項

- 本タスクで実装する消耗投資項目（触媒・種の指名買い）に「ターン延長」に相当する項目を一切含めないこと。REQ-303（金でターンを延長できない、設計上の核心制約）の横断検証はTASK-0036で行う
- 消耗投資はREQ-305により購入タイミングの制限を持たない点が恒久投資（TASK-0034、REQ-304でランク間限定）との最大の違いであり、実装・テストの両方でこの非対称性を明示すること
- 価格の具体値はTBD（REQ-306）であり、`balance-tuning-cycle`等の後続バランス調整で確定させる
