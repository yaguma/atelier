## タスク概要

TASK-0013〜0017で実装した個別の純粋関数（品質計算・特性発現判定・系統排他制御・品質ペナルティ・貢献度/報酬算出）を1つの調合オーケストレーター関数`AlchemyResolver.craft()`に束ねる。

本タスクはGodotアーキテクトレビュー **Warning#2** への直接対応として新設された設計である。旧設計案ではUI（`AlchemyBench`）が`QualityCalculator`→`TraitActivation`→`ValueCalculator`を個別に直接呼び出す想定だったが、これは調合ワークフローというビジネスロジックがUIに漏れ、「UIはビジネスロジックを持たない」という原則に反する。`AlchemyResolver.craft()`という単一の純粋関数にこの一連の処理を集約することで、UI（TASK-0020）は投入枠の選択操作と結果表示のみを担当できるようになる。

dataflow.md「機能2: 調合」が明記する5ステップ（base_quality算出→特性発現判定→系統排他→品質ペナルティ→貢献度/報酬算出）を、TASK-0013〜0017の関数呼び出しの合成として実装する。

### 2. オーケストレーションの5ステップ 🔵

**信頼性**: 🔵 *dataflow.md「機能2: 調合」のシーケンス図注記より*

```gdscript
static func craft(...) -> CraftResult:
    # EDGE-001ガード: 投入枠が空の場合は調合を成立させない
    if materials.is_empty():
        return null  # または呼び出し元が判別可能な特別値（詳細は「注意事項」参照）

    # 1. calculate_base_quality(投入素材) — REQ-105
    var base_quality := QualityCalculator.calculate_base_quality(materials)

    # 2. resolve_activated_traits(投入素材, reveal_level) — REQ-106, REQ-112
    #    同一特性2個以上のみ発現候補化。同一系統内は複数同時発現可
    var candidate_traits := TraitActivation.resolve_activated_traits(materials, reveal_level, trait_definitions)

    # 3. resolve_category_conflict(発現特性) — REQ-115
    #    貢献度系/報酬系が同時に条件を満たす場合、枚数の多い系統のみ採用
    var conflict_result := TraitActivation.resolve_category_conflict(materials, candidate_traits)
    var final_traits: Array[TraitDefinition] = conflict_result["activated_traits"]

    # 4. apply_trait_penalty(基礎品質, 最終発現特性) — REQ-111
    #    発現特性1個につき品質-1段（加算的）、補助系(触媒)は事後+1段
    var final_quality := QualityCalculator.apply_trait_penalty(base_quality, final_traits)

    # 5. calculate_contribution / calculate_reward — REQ-109, REQ-110
    #    最終品質・最終発現特性・指定合致ボーナスを用いて算出
    var contribution := ValueCalculator.calculate_contribution(recipe, final_quality, final_traits, daily_request)
    var reward := ValueCalculator.calculate_reward(recipe, final_quality, final_traits, daily_request)

    var result := CraftResult.new()
    result.base_quality = base_quality  # 🟡 float→Quality enum変換が必要（TASK-0013/0016の申し送り参照）
    result.final_quality = final_quality
    result.activated_traits = final_traits
    result.rejected_category = conflict_result["rejected_category"]
    result.contribution = contribution
    result.reward = reward
    return result
```

**実装ファイル**: `features/alchemy/logic/alchemy_resolver.gd`

### 3. EDGE-001（投入枠が空）のガード実装方針 🟡

**信頼性**: 🟡 *EDGE-001、dataflow.md「エラーハンドリングフロー」より妥当な推測*

dataflow.mdの「エラーハンドリングフロー」は「投入枠が空/EDGE-001 → 調合ボタンを非活性化し実行不可にする」というUI側の予防的制御を基本方針としているが、`AlchemyResolver.craft()`自体も純粋関数としての防御的実装を持つべきである（UI側の制御漏れに対する二重の安全策、architecture.md「非機能要件の実現方法」の設計思想を踏襲）。戻り値の表現方法（`null`を返すか、`CraftResult`に`is_valid: bool`相当のフラグを追加するか）はdata-model.mdに明記がないため、本タスクでは`null`を返す方式を暫定採用する。呼び出し元（TASK-0019のGameState）は`null`チェックを行い、調合を成立させないこと。

## 注意事項

- **Godotアーキテクトレビュー Warning#2対応の経緯（最重要）**: 本関数は「UIがビジネスロジックを個別に直接オーケストレーションする」設計上の欠陥を解消するために新設された。実装時にUI（TASK-0020）や将来の別機能から`QualityCalculator`・`TraitActivation`・`ValueCalculator`を個別に直接呼び出すコードを書かないこと。調合の一連の計算は必ず`AlchemyResolver.craft()`を経由させる。
- 本タスクはTASK-0013〜0017で申し送られた複数の未確定事項（float→int変換ポイント、`trait_definitions`/`recipe`引数の追加、`rejected_category`の無効値表現、指定合致ボーナスの二重適用疑義）を統合する箇所である。実装着手前にこれらの申し送り事項を再確認し、一貫した方針で実装すること。
- 本関数はGameState等のAutoloadを一切参照しない（`reveal_level`・`daily_request`・`recipe`・`trait_definitions`はすべて引数として受け取る）。この境界を破らないことがGodotアーキテクトレビューCritical#1・Warning#2双方の対応の核心である。
