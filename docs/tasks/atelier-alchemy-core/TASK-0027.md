## タスク概要

ギルド納品・ランク進行フェーズの基盤となる2つのデータモデルを実装する。`RankDefinition`（HPを持つ「ギルドランク」を敵として表現するResource。REQ-401）と `DailyRequest`（1日ごとにギルドが提示する日替わり指定調合物。REQ-203）を、data-model.md記載の型定義に従って実装する。両クラスは後続タスク（TASK-0028のDeliveryCalculator、TASK-0029〜0030のGameState納品・ランク判定処理、TASK-0031のランク進行順序管理）から参照される基礎データ構造であり、本タスクではデータ構造そのものと、コンストラクタ・デフォルト値の妥当性を検証する。

## 依存タスク

- **前提タスク**: TASK-0002（他フェーズ実施想定。Feature-Basedディレクトリ構造の存在を前提とするためリンクのみ）
- **後続タスク**: [TASK-0028](TASK-0028.md), [TASK-0031](TASK-0031.md)

- [ ] `features/guild/data/daily_request.gd` が `class_name DailyRequest` / `extends RefCounted` として作成され、`required_recipe_id`, `preferred_category`, `bonus_multiplier` を保持する

## 実装詳細

### 1. RankDefinition（ランク定義）実装 🟡

**信頼性**: 🟡 *data-model.md「ランク定義（RankDefinition）」より。正式なランク区分・数値はTBD*

REQ-401「ランクごとにHPを持つ『ギルドランク』を敵として表現しなければならない」に基づき、Resourceとして実装する。`trait_reveal_level` は段階的開示（REQ-121〜124）に使用される値で、0=特性なし（Gランク）、1=貢献度/報酬解禁（Eランク以降）、2=特性種類追加（Dランク以降）に対応する（🔵 data-model.mdコメントより確定）。この対応関係はTASK-0031でランク進行順序と合わせて管理し、Phase 6（TASK-0037想定の段階的開示実装）が参照できるようにする。

```gdscript
# res://features/guild/data/rank_definition.gd
class_name RankDefinition
extends Resource

@export var id: StringName            # 例: "G", "F", "E"... REQ-403より。正式名称はTBD
@export var max_hp: int = 100         # REQ-401。具体値はTBD（balance-tuning-cycleで確定）
@export var turn_limit: int = 10      # REQ-205「制限ターン」。具体値はTBD（balance-tuning-cycleで確定）
@export var trait_reveal_level: int = 0
	# REQ-121〜123の段階的開示に使用（0=特性なし, 1=貢献度/報酬解禁, 2=種類追加）
```

**実装ファイル**: `features/guild/data/rank_definition.gd`

### 2. DailyRequest（日替わり指定調合物）実装 🔵

**信頼性**: 🔵 *data-model.md「日替わり指定調合物（DailyRequest）」、要件REQ-203, REQ-204より*

REQ-203「1日ごとにギルドが求める『日替わり指定調合物』を1件提示しなければならない」に基づき、RefCountedとして実装する。`preferred_category` と `bonus_multiplier` はREQ-204の指定合致ボーナス判定（TASK-0028のDeliveryCalculator）で使用される。

```gdscript
# res://features/guild/data/daily_request.gd
class_name DailyRequest
extends RefCounted

var required_recipe_id: StringName       # REQ-203
var preferred_category: TraitDefinition.Category  # 貢献度系/報酬系どちら向きを指定するか。REQ-204より妥当な推測
var bonus_multiplier: float = 1.5        # REQ-204の指定合致ボーナス。具体値はTBD（balance-tuning-cycleで確定）

func _init(p_recipe_id: StringName = &"") -> void:
	required_recipe_id = p_recipe_id
```

**実装ファイル**: `features/guild/data/daily_request.gd`

### 3. TBD値のコメント明記 🟡

**信頼性**: 🟡 *未確定数値一覧（requirements.md）より*

`max_hp`, `turn_limit`, `bonus_multiplier` はいずれも要件定義書「未確定数値一覧」に記載のTBD項目であるため、デフォルト値には「balance-tuning-cycleスキル等で後続確定」であることを示すコメントを付与する。本タスクではデフォルト値そのものの正しさではなく、データ構造としてこれらの値を保持・受け渡しできることを検証する。

## 注意事項

- `max_hp`, `turn_limit`（REQ-205）, `bonus_multiplier`（REQ-204）の具体的数値はTBDであり、balance-tuning-cycleスキル等の後続バランス調整フェーズで確定させる。本タスクではデータ構造としての妥当性のみを検証し、数値そのものの正しさは検証範囲に含めない
- `DailyRequest.preferred_category` の型は `TraitDefinition.Category`（`features/alchemy/data/trait_definition.gd`）に依存するため、TASK-0011（TraitDefinition実装、他フェーズ）が完了済みであることを前提とする
- ランクの正式な区分名・数（REQ-403）はTASK-0031で扱うため、本タスクでは `RankDefinition.id` のフォーマット（StringName）のみを規定し、具体的な一覧は定義しない
