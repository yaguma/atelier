## タスク概要

収穫実行時に素材へ特性タグを1つ、乱数で付与する `TraitRoll` をFunctional Core（純粋関数）として実装する。REQ-006の「分散のみで期待値は変えない」という制約を満たすため、`possible_traits` から一様分布で1件を選択するロジックとし、RngServiceから渡されたシード値を引数として受け取ることで再現性・テスト容易性を確保する（Autoloadを直接参照しない）。

## 実装詳細

### 1. 特性抽選 `roll_trait` 🔵

**信頼性**: 🔵 *REQ-006「収穫実行時に素材へ特性タグを1つ、乱数（分散のみで期待値は変えない）で付与」より*

```gdscript
# res://features/garden/logic/trait_roll.gd
class_name TraitRoll

static func roll_trait(seed_def: SeedDefinition, rng_seed: int) -> StringName:
	if seed_def.possible_traits.is_empty():
		return &""
	var rng := RandomNumberGenerator.new()
	rng.seed = rng_seed
	var index: int = rng.randi_range(0, seed_def.possible_traits.size() - 1)
	return seed_def.possible_traits[index]
```

`possible_traits` からのインデックス選択は一様分布（`randi_range`）とし、いずれの候補も等しい確率で選ばれるようにする。これにより「分散のみで期待値は変えない」（REQ-006）— すなわち特定の特性を優遇せず、結果にランダム性（分散）のみを持たせるという要件を満たす。

**実装ファイル**: `features/garden/logic/trait_roll.gd`

### 2. シード引数によるAutoload非依存設計 🔵

**信頼性**: 🔵 *architecture.md「ランク等の外部状態はAutoload参照ではなく必ず引数で受け取る」原則、タスク概要の指示（RngServiceから受け取ったシードを引数で受ける設計とし、Autoload参照はしない）より*

`RngService`（Autoload、TASK-0004）が管理するシード生成・消費のロジックには関与せず、本クラスは呼び出し元（GameState等のImperative Shell）が渡した `rng_seed: int` のみを使用する。これにより `TraitRoll` はGUT等でシーン起動なしに単体テスト可能であり、同一シードに対して常に同一結果を返す決定的な関数となる。

**実装ファイル**: `features/garden/logic/trait_roll.gd`

### 3. 特性候補が空の場合の扱い 🟡

**信頼性**: 🟡 *data-model.mdの `possible_traits: Array[StringName] = []`（空配列を許容する型）より妥当な推測*

`possible_traits` が空の種（特性を一切持たない種、あるいはGランクの段階的開示で特性が無効化されている状況を想定したデータ構成）に対しては、空文字列相当の `StringName`（`&""`）を返し、特性なしとして扱う。呼び出し元（GameState）はこの戻り値が空である場合、`MaterialInstance.traits` に要素を追加しない。

**実装ファイル**: `features/garden/logic/trait_roll.gd`

## 単体テスト要件

### テストケース1: TC-006-01 収穫時に特性が1つ付与される 🔵

**信頼性**: 🔵 *acceptance-criteria.md TC-006-01より*

**Given**: 特性候補を複数持つ `SeedDefinition`（例: `possible_traits = [&"seibi", &"jou", &"iyashi"]`）
**When**: `roll_trait(seed_def, rng_seed)` を呼び出す
**Then**: 戻り値が `possible_traits` のいずれか1件と一致する（空文字列ではない）

**テストファイル**: `tests/unit/features/garden/trait_roll_test.gd`

### テストケース2: TC-006-S01 特性乱数の分散が期待値を変えないことを統計的に確認する 🟡

**信頼性**: 🟡 *acceptance-criteria.md TC-006-S01「同一種を統計的に十分な回数（例: 100回以上）収穫する」より。具体的な統計的許容範囲は実装フェーズで確定するため許容誤差は妥当な推測値*

**Given**: 特性候補を3件持つ `SeedDefinition`
**When**: 異なる `rng_seed`（0〜999等の連番）で `roll_trait` を300回以上呼び出し、各特性の出現回数を集計する
**Then**: 各特性候補の出現比率が理論値（1/3）から大きく偏らない（例: 許容誤差 ±10%ポイント程度）。極端な偏り（特定の1件のみが選ばれ続ける等）が発生しないことを確認する

**テストファイル**: `tests/unit/features/garden/trait_roll_test.gd`

### テストケース3: 同一シードに対する決定性 🔵

**信頼性**: 🔵 *architecture.md「純粋関数は同じ入力に対して常に同じ出力」の原則より*

**Given**: 同一の `SeedDefinition` と同一の `rng_seed`
**When**: `roll_trait` を複数回呼び出す
**Then**: 毎回同一の特性タグが返る（決定性の確認）

**テストファイル**: `tests/unit/features/garden/trait_roll_test.gd`

### テストケース4: 異常系 - 特性候補が空の種 🟡

**信頼性**: 🟡 *data-model.mdの空配列許容型より妥当な推測*

**Given**: `possible_traits` が空配列の `SeedDefinition`
**When**: `roll_trait(seed_def, rng_seed)` を呼び出す
**Then**: 空文字列相当の `StringName`（`&""`）が返り、例外やクラッシュが発生しない

**テストファイル**: `tests/unit/features/garden/trait_roll_test.gd`

## 注意事項

- 本クラスは `RngService`（Autoload）そのものへの参照を持たない。呼び出し元（GameState）が `RngService` からシードを取得し、引数として渡す責務を負う（依存の方向を明示的に管理する）
- TC-006-S01の統計的検証は乱数を扱うテストのため、GUTのテスト実行時間・安定性に配慮し、試行回数は必要最小限（300回程度）に留める。テストが稀に閾値付近で不安定になる場合は許容誤差の調整を検討する
- `possible_traits` の内容（実際の特性IDと`TraitDefinition`との整合）はTASK-0011（他フェーズ）のスコープであり、本タスクでは文字列としての妥当性のみを扱う
