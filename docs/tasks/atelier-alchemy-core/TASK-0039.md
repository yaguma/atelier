## タスク概要

プレイヤーが実際に一連のループ（種を植える→収穫→調合→自動納品→ランクHP減少→昇格試験→工房強化→次ランク）を最初から最後まで手動でプレイし、要件定義書の全ユーザストーリー（エピック1〜4）が成立することを確認する。design-interview.mdのヒアリングで「GUTでの自動E2Eは本タスクのスコープ外とし、手動プレイ検証チェックリストとして実施する」と確定した通り、本タスクは自動テストコードを新規実装するのではなく、TASK-0038で完成した`scenes/main.tscn`を実際にGodotエディタで起動し、チェックリストに沿ってプレイして結果を記録する検証タスクである。

## 実装詳細

### 1. 検証環境の準備 🟡

**信頼性**: 🟡 *DIRECTタスクの一般的な準備手順として妥当な推測*

**対象ファイル**: `atelier-godot/project.godot`, `atelier-godot/scenes/main.tscn`

### 2. 手動プレイ検証チェックリストの実施 🔵

**信頼性**: 🔵 *user-stories.mdエピック1〜4、requirements.mdの各REQ、acceptance-criteria.mdの各TCより網羅的に構成*

下記チェックリストに沿って、実際にゲームをプレイしながら1項目ずつ確認する。

**実施方法**: 手動プレイ（Godotエディタでの実行 + 目視確認）。必要に応じて`playwright-mcp.md`のような自動操作ツールは使用せず、実際の入力デバイスでプレイする（GodotゲームはWebベースではないため）。

**対象ファイル**: なし（検証行為そのもの。結果はチェックリストへの記録として本タスクの成果物とする）

## 手動プレイ検証チェックリスト（動作確認要件）

### エピック1: 庭で素材を仕込む

- [ ] **チェック1-1**（ストーリー1.1, REQ-001, REQ-008）: 庭のスロットに空きがある状態で、手持ちの種を選択して植えられる
- [ ] **チェック1-2**（REQ-003）: 植えた種ごとに異なる成熟ターン数が管理され、ターン経過で成熟状態に変化する
- [ ] **チェック1-3**（ストーリー1.2, REQ-004, REQ-005）: 成熟後、収穫せず放置すると品質が上昇する一方、規定ターンを超えると枯死する
- [ ] **チェック1-4**（REQ-007, EDGE-003）: 成熟前の素材は収穫操作自体が行えない（UI上で収穫不可として扱われる）
- [ ] **チェック1-5**（REQ-006）: 収穫実行時に特性タグが1つ付与される（複数回収穫して分散があることを確認する。期待値は変えない）
- [ ] **チェック1-6**（EDGE-002）: 庭のスロットが全て埋まっている状態で新たな種を植えようとすると拒否される

### エピック2: 調合台で品を練り上げる（★核心）

- [ ] **チェック2-1**（ストーリー2.1, REQ-101, REQ-105, REQ-106）: 投入枠（初期4枠）に素材を配置し、品質の平均値が基礎品質として算出され、同一特性2個以上でのみ特性が発現する
- [ ] **チェック2-2**（REQ-111, REQ-112）: 発現特性1個につき品質が1段階減算され、複数特性同時発現時はペナルティが加算的に積み重なる
- [ ] **チェック2-3**（REQ-115）: 貢献度系・報酬系が同時に条件を満たす場合、枚数の多い系統のみが発現し、同数の場合はどちらも発現しない
- [ ] **チェック2-4**（ストーリー2.2, REQ-107, REQ-109, REQ-110）: 貢献度系特性を狙った調合と報酬系特性を狙った調合を両方実際に行い、狙い通りの価値（貢献度 or 報酬）が得られる
- [ ] **チェック2-5**（EDGE-001）: 投入枠に素材が1つも入っていない状態では調合を実行できない

### エピック2補足: 段階的開示（ストーリー2.3, TASK-0037）

- [ ] **チェック2-6**（REQ-121, NFR-201）: Gランクでは特性付き素材を投入しても特性が一切発現せず、UI上にも特性関連の情報が一切表示されない
- [ ] **チェック2-7**（REQ-122）: Eランクへ到達すると、貢献度系・報酬系特性の発現・表示が解禁される
- [ ] **チェック2-8**（REQ-124）: Gランクの間、Dランク以降解禁の特性を持つ種・素材が庭・ショップの選択肢に一切表示されない

### エピック3: ギルドに納品してランクを上げる

- [ ] **チェック3-1**（ストーリー3.1, REQ-201, REQ-202）: 調合完了後、プレイヤー操作なしに完成品が自動でギルドへ納品され、貢献度・報酬が加算される
- [ ] **チェック3-2**（ストーリー3.2, REQ-203, REQ-204）: 日替わり指定調合物が1日ごとに提示され、合致する納品でボーナスが加算される
- [ ] **チェック3-3**（ストーリー3.3, REQ-205, REQ-206）: 残りターン数が画面上で確認でき、制限ターン内にランクHPを0にできれば昇格試験へ、できなければ降格処理が行われる

### エピック4: 金を投資して工房を強化する

- [ ] **チェック4-1**（ストーリー4.1, REQ-301, REQ-304）: ランクHPを0にして昇格試験をクリアすると工房強化画面が開き、恒久投資（投入枠+1・庭拡張・レシピ解禁）を選択できる
- [ ] **チェック4-2**（REQ-102）: 投入枠+1を購入すると、次ランク以降の調合台の投入枠が5枠になっている
- [ ] **チェック4-3**（ストーリー4.2, REQ-302, REQ-305）: 通常ターン中いつでもショップを開き、触媒の購入・種の指名買いができ、購入した触媒がそのターンの調合ですぐ使える
- [ ] **チェック4-4**（ストーリー4.3, REQ-303）: 工房強化画面・ショップのいずれにも「ターン延長」に相当する購入項目が存在しないことを目視で確認する

### 全体ループの一巡確認

- [ ] **チェック5-1**（dataflow.md「システム全体のデータフロー」）: 種を植える→収穫→調合→自動納品→ランクHP減少→（ランクHP0到達時）昇格試験→工房強化→次ランクへの復帰、という一連の流れを最初から最後まで途切れなく操作できる
- [ ] **チェック5-2**: 上記の一巡中、クラッシュ・フリーズ・ボタン無反応（signal未接続の疑い）が発生しない
- [ ] **チェック5-3**（EDGE-104）: 制限ターンちょうどでランクHPが0になった場合、降格処理ではなく昇格試験への移行として扱われる

## 注意事項

- 本タスクはGUTによる自動E2Eテストの実装をスコープに含めない（design-interview.mdの追補ヒアリングで明確に確定した方針）。将来的に自動化する場合は別タスクとして切り出すこと
- NGが見つかった場合、本タスク自体で実装修正は行わず、原因となった該当タスク（TASK-0001〜TASK-0038のいずれか）に修正が必要である旨を記録し、修正は当該タスクの再オープンまたは新規のfixタスクとして扱う
- REQ-109, REQ-110, REQ-205, REQ-206, REQ-306等、多数のバランス数値がTBDであるため、「体験として違和感がないか」程度の定性的確認に留め、具体的な数値の妥当性判断（面白いかどうかのバランス調整）は`balance-tuning-cycle`スキル等の後続フェーズで行う
- 本タスクの完了をもって、Phase 1〜6（atelier-alchemy-coreのタスク分割スコープ全体）の主要な結線・統合が完了したとみなす
